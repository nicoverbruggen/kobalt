# Progress sync

Open Settings → Sync to sign in with an existing KOSync account. Sign in, Sync now, Sign out and Learn more use left-aligned, vertically centered labels, with the same inset as the account rows. Enter your server URL. Until a server is set, the field starts with `https://`. Saving only that prefix leaves the server unset. The server must use HTTPS. Include a path prefix if the server is hosted under one. Do not include credentials, a query or a fragment in the URL. Kobalt does not register new accounts. Device name defaults to the detected model followed by “(Kobalt)”. Edit it to choose a custom name, or clear the field to restore the default. Mac uses its hardware model identifier; unrecognized Kobo models use “Kobo (Kobalt)”. The device ID stays the same when the name changes. The Sync page shows the last successful progress sync for this account on this device in local time. This timestamp survives restarts. Failed or cancelled attempts do not change it.

Without a successfully authenticated account, KOSync does not start periodic checks, prepare a network connection, delay opening or show a sync prompt. Signing out or disabling automatic sync stops periodic syncs. With automatic sync disabled, eligible books show a manual sync button beside Search in the top toolbar. The button is hidden when signed out or when automatic sync is enabled. The first tap explains manual sync and offers Sync now or Cancel. Confirming remembers the explanation; later taps sync immediately. Cancel keeps the explanation for the next tap. Manual mode does not sync on open, close, sleep or wake. Signing in prepares a connection only after the user requests it.

Account editors keep focus on the text field when tapping the keyboard. Key presses do not move focus to the modal backdrop or refresh the whole screen.

The password editor starts with masked text. Tap Show to reveal the password and Hide to mask it again. Both actions keep the cursor, selection and keyboard in place. Closing the editor or moving the app to the background masks the password. Reopening the editor always starts masked. The visibility choice is not saved.

Downloaded Kobo titles, including Kobo Cloud EPUBs, use Kobo's own progress sync. The Sync tab names the service that syncs the open book and explains how to add a separate DRM-free copy. Learn More explains the two sync systems and what KOSync transfers. Account fields, sync controls and KOSync status are hidden for these books. Sideloaded EPUB and KEPUB files remain eligible for KOSync, including when opened from Kobo's library. Their local Nickel progress continues to be saved. Standalone desktop and Android books use KOSync.

Automatic sync is enabled after a successful sign-in. The Automatic sync row on the Sync page names the current schedule and opens the Automatic sync sheet. The sheet has an Off and On choice and lists when Kobalt syncs. With automatic sync off, the rest of the sheet stays visible in gray and the toolbar has a manual sync button. While you read comes first. It syncs a changed position at the chosen interval: every page (at most every 30 seconds), every minute, every 5, 15 or 30 minutes, every hour, or never. The default is every 15 minutes. There is no timer: when the reader shows a new position, it syncs if the interval has passed since the last sync. A book left open does not sync until the next page or, if those syncs are on, sleep or close. When you open a book, When your device sleeps or wakes, and When you close the book each have a checkbox, on by default. Tapping anywhere on the row toggles it. The sheet shows only the moments the platform has. Kobo offers sleep and wake and the Wi-Fi choice. Desktop and Android leave both out: desktop has no device sleep, and on Android leaving the app only saves a local checkpoint. The desktop e-reader previews show the Kobo moments, and the phone previews show the Android ones. The interval list opens over the sheet and pages on short screens. A periodic sync only contacts the server when the position differs from the last successfully synchronized position. When Wi-Fi is off, Wait keeps the position local until a later sync finds a connection. Turn on Wi-Fi connects silently for the periodic sync and turns Wi-Fi off again when that sync ends. Kobalt turns Wi-Fi off only when it turned it on for this sync. A connection that was already up, or that the user started, stays on. Turning Wi-Fi off waits briefly on the main thread; see [the main-thread guard](../validation.md#main-thread-guard). After three background connections in a row find no network or get no answer within the ten-second sync deadline, periodic syncs stop trying until the device wakes, the user taps Sync now or a sync finds Wi-Fi connected. This count lives in memory only. Opening and waking connect silently as before, whatever the Wi-Fi choice. With Never, the Wi-Fi choice is gray. The time of a successful sync is saved in the background; a failed save is logged and shows no message. Failed attempts remain eligible for retry. Opening keeps the loading screen for up to 0.5 seconds while sync runs. If sync is still pending, Kobalt presents the reader with a cancellable Syncing popover while the same request continues. Cancel sync cancels that attempt. Sync now shows the same popover after connection preparation finishes. After a successful sync, any visible Syncing popover changes to Sync complete and confirms that reading progress is up to date. It has no button and closes automatically after 1.5 seconds. On Kobo, this visible confirmation briefly prevents CPU standby so its dismissal timer can finish. Sleeping or closing the reader dismisses it immediately. Background checks and fast opening checks that show no popover stay quiet. A required position choice replaces the progress popover without showing success first. If the reader is still busy when a server response arrives, sync waits for the reader within the same deadline and then continues without fetching the response again. An unsuccessful opening check returns to the saved local position after at most ten seconds. Opening, wake and manual reads retry transient connection failures after 0.5, 1.5 and 3 seconds, within that same ten-second budget, so a connection can recover after wake. Cancellation stops scheduled retries. Periodic reading checks and final close/sleep reads keep one attempt. Uploads, HTTP failures and TLS failures are not retried automatically. Sign-in reads use the same bounded retry behavior. It fetches the server position before sending a changed local position. A failed request leaves the local position saved and retries on a later check. Closing or sleeping saves the local position first and allows up to two seconds for a final sync. An in-flight upload finishes before the final attempt starts, within the same deadline. Unresolved remote conflicts are never overwritten during a final attempt. On Kobo, the sleep view can appear immediately while this bounded attempt briefly prevents CPU suspension. If no connection is available, the saved position is retried when the book reopens or wakes. Closed books do not upload in the background. Sync now also works with automatic sync disabled.

A different position from another device asks before moving. The choice compares the local and remote chapters and percentages, and shows the remote device and sync time in local time. Kobalt resolves the remote chapter and source order on its engine worker without moving the reader. Backward moves have a warning heading and focus Keep this position. The reported percentage does not decide direction. Unresolvable positions show an unavailable chapter and direction; missing device names or timestamps are stated as unavailable. Keep this position sends the local position on the next sync. Use synced position opens the received CREngine position and saves it locally. The choice waits while Settings or another reading tool is open. An invalid position leaves the book readable, blocks automatic uploads and disables automatic sync. Use Sync now to revisit the choice. Exact position compatibility with KOReader depends on both readers producing compatible document structures.

Document matching defaults to Binary, using KOReader's partial-file MD5 algorithm. Use the same EPUB file on each device; renaming it does not change its sync identity. Choose Filename to match the MD5 of the exact UTF-8 filename, including case and extension. Different files with the same filename then share progress. Choose the same method on every reader. Changing the method clears the displayed last-sync timestamp and checks the selected identity on the next sync. It does not copy or merge progress between identities. On Android, Kobalt retains the original source filename rather than using its internal cache name. Reimport older standalone imports to make their original filename available. Sync transfers reading positions, percentages and a device identifier. It does not transfer books, bookmarks or annotations. Local reading data remains available after signing out.

On Kobo Qt5 and Qt6, Sign in and Sync now use Nickel's interactive Wi-Fi connection workflow when needed. Opening and waking use silent reconnect, which respects disabled Wi-Fi and Nickel's battery restrictions. Automatic connection preparation shares the attempt's ten-second deadline with the progress exchange. Manual connection preparation pauses its connection timeout while Nickel is asking for permission, network selection or a password. The ten-second progress-exchange deadline starts after that preparation finishes. Cancel sync stops the connection wait and cancels a native workflow started by that attempt. It does not cancel a connection started by another native caller. A usable local IPv4 connection permits a custom server even if Nickel's public internet check fails. Periodic reading checks and final close/sleep attempts use an available connection without reconnecting. Kobalt does not force Wi-Fi to stay on or turn it off after syncing. Nickel retains radio power management. KOSync does not start or subscribe to Kobo's full sync.

On Kobo Qt5, sync resolves the server separately before sending each request. This avoids waiting behind an older cancelled lookup in Qt's shared DNS queue. If the first lookup fails or takes more than one second, sync tries one fresh lookup within the same ten-second deadline. This also applies to Sync now and uploads because no HTTP request has been sent yet. Closing, sleeping or cancelling prevents the lookup from starting a later request. HTTPS certificate checks remain enabled.

Failed sign-in, position reads and uploads show the specific failure instead of a generic saved-locally message. Messages distinguish name resolution, refused or closed connections, TLS trust or handshake failures, deadlines, HTTP rejection and incompatible responses. HTTP 401 asks the user to check credentials and account existence. HTTP 403 asks the user to check permissions. A route error or redirect asks the user to check the URL and path prefix. The endpoint must support KOSync’s `x-auth-user` and `x-auth-key` authentication. A service name alone does not establish compatibility. Kobalt does not forward credentials through redirects or disable certificate verification. Failed syncs keep the local reading position.

When no connection is available, sync says so and asks the user to connect to Wi-Fi. This also applies when periodic sync waits for Wi-Fi or a final sync has no connection. No KOSync request is sent in these cases. A connection preparation deadline reports that no connection became available before the timeout.

For a book without server progress, Kobalt accepts the reference server’s empty HTTP 200 response and the exact HTTP 404 JSON object `{"status":"not found"}` used by compatible servers. It can then upload the first position. Other 404 responses remain errors, so an invalid server route cannot start an upload. A recognized absent-progress response does not bypass an unresolved position choice. See the [progress API contract](../validation/kosync.md#progress-api-contract) for response rules and regression checks.
