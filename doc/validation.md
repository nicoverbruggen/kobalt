# Native validation

On Linux, `platform.screensaver-loader` verifies that Screensaver discovery opens library handles only after `dl_iterate_phdr` returns. This prevents a loader-lock inversion with concurrent library loading. The shutdown tests retain coverage of both Screensaver hook orders and delayed saves.

`platform.startup-recovery` checks repeated interrupted initialization, successful retries, later stock-reader crashes, normal shutdown, legacy marker migration, timestamp-independent failure counts, a retry after damaged records, durable removal notices and their cleanup after recovery, failed notice writes, and refusal of unsafe or unavailable storage. It exercises the production recovery file handling without a Kobo. Full loader removal and restart behavior also require device validation.

`model.crash-reports` crashes child processes with a fault and with `abort`. Each report must name the signal and contain the backtrace and symbol sections, and the fault report must name the crashing function. The previous handler must still run after each report. A full set of reports must keep the newest ones and leave other files alone. Without the mounted storage, no report may be written. Register capture and stack scanning for ARM Linux run only on a Kobo; read a report on a device after a crash to check them.

Return-header checks require one button covering the arrow and title, the Library label for standalone readers, and the default Exit Kobalt label for the native host. Pixel checks require a 6-point arrow-to-text gap and check the optical vertical offsets of the arrow and label. They check both return captions in both themes and screen sizes. Arrow and title taps share one pressed state and close the book; close/reopen tests retain the saved position. Exit ignores a tap pressed within 400 ms of the tap that closed Settings or a list in the same cell. The lifecycle check compares press times, so a tap that only waited while a slow close held the GUI still exits. The light and full galleries capture the combined pressed state. Existing menu captures show the shared header in both themes and reader sizes.

Use a prepared native Qt 6.11 or newer Qt 6 SDK. Configure once as described in [Building](building.md). The examples below use Mac; Linux has corresponding `linux` presets. Desktop defaults to sensorless orientation. Enable `KOBALT_DESKTOP_SENSORS` for sensor lock/debounce and borrowed-sensor handoff checks; the default suite retains manual rotation and sensorless lifecycle assertions. Run the commands below from `platforms/desktop/`. They use this checkout's code, assets and incremental cache. No device, firmware, Python or private service is required.

## KOsync

`lifecycle.kosyncAccountGating` checks missing, signed-out, unauthenticated, malformed and unsupported accounts. It requires no periodic timer, connection preparation, opening delay, sync prompt or HTTP request. It also checks timer changes and toolbar button visibility when automatic sync is disabled and enabled, and when the user signs out. `lifecycle.kosyncManualToolbar` checks first-use confirmation and cancellation, interactive connection preparation, busy button gating, subsequent immediate sync, restoring the explanation from Settings and skipping sleep sync in manual mode. The full screenshot gallery includes the manual toolbar, explanation, Settings, sync progress and success in both themes and reader sizes.

Kobo always writes bounded diagnostics. Sync events record native connection preparation and completion, radio state and signal strength, completed and cancelled request error codes, HTTP status and timing, and deadline and TLS stages. On Qt5, lookup start and completion events separate DNS resolution from HTTP and TLS. Cancelled lookups cannot start an HTTP request. A reader-wait event records the busy, visibility and native suspension flags once when a successful response must wait for the reader. Sync events exclude URLs, authentication, response bodies and book IDs. Read `.adds/kobalt/diagnostics/events.jsonl` after reproducing a failure.

The platform check also composes the production presentation layer with native-shaped dialogs to verify visibility above the paused backing store, input guards, nested modal ownership, cancellation, reader hiding, preserving native fonts and colors across reader theme changes, restoring native window flags and allowing time to answer a native permission prompt. Substituted native Wi-Fi signals check signal strength, invalid reports, radio shutdown and subscription lifetime. `lifecycle.kosyncManualConnection` verifies that manual connection preparation does not consume the progress-exchange deadline, that the cancellable Syncing notice appears above Settings only after connection preparation, and that desktop sync uses the same notice. It checks blocked page input, cancellation and usable Settings after dismissal. Set `KOBALT_KOSYNC_MANUAL_CAPTURE` to an absolute PNG path to capture that notice. `lifecycle.wifiStatus` checks dynamic indicator placement beside Bluetooth and the battery, including Wi-Fi occupying Bluetooth’s center when Bluetooth is off, a full-signal glyph at 90% of Bluetooth’s visible height, centered one density-scaled pixel above its intersection, status changes, hidden radios and hiding disconnected, unknown or zero-strength Wi-Fi in light and dark mode at both UI densities. `model.kosync` checks partial-file and exact-filename identification, matching defaults and persistence, timestamp reset and busy-state protection when switching modes, unsupported matching values, custom HTTPS URL prefixes, authentication headers and password hashing, account persistence and permissions, manual-explanation defaults and persistence through account edits, last-sync persistence and account changes, editable device names and stable identity, sign-out, malformed and oversized responses, HTTP failures, bounded transient read retries, retry cancellation, rejection of TLS/HTTP/upload retries, and unsupported account schemas. Controlled resolver calls check the two-worker limit across cancelled readers, lookup deadlines, immediate cancellation and destruction, suppressing late HTTP dispatch, a fresh lookup while the cancelled lookup is blocked, automatic recovery within one sign-in or manual pull, one upload dispatch after DNS recovery, cancellation during the second lookup, and retaining the HTTPS hostname. Numeric server addresses skip resolution. It uses a controlled network transport and never contacts a public sync service.

On Qt5, KOsync resolves each request's hostname on a separate worker before HTTP. This bypasses Qt5's shared asynchronous lookup queue and fills Qt's hostname cache. The request keeps its original URL and TLS verification. The first DNS subattempt has a one-second limit. A failed or timed-out lookup gets one fresh subattempt with the remaining request budget. This recovery is independent of HTTP retries: it applies to manual reads and uploads before dispatch, and never replays an upload after a transport failure. Diagnostics include `lookup_attempt` to distinguish the two subattempts. libc cannot cancel a running lookup, so at most two calls can finish in the background after cancellation; no new calls are queued while both workers are occupied. Reader close and sleep do not wait for those calls or retain a suspend blocker for them. Application shutdown joins the workers before Qt's process-wide resolver cache is destroyed. This bounds concurrency, but the operating system still controls the duration of a running DNS call.

`component.kosync-ui` checks left-aligned, vertically centered action labels in both themes at 212 and 300 PPI, the dedicated Settings tab, account controls, the host keyboard, blank initial server, last-sync display and tab order, device-name entry and reset, matching selection and cancellation, keyboard-safe dialog placement, input focus during native-key ancestor fallback, masked password entry, deferred keyboard cleanup, automatic-sync selection and page dismissal. The sync notice check verifies cancellation while syncing, a button-free success state, the 1.5-second automatic dismissal and cancelling its timer when hidden. Password checks cover Show and Hide, retained cursor and selection, typing after reveal, sensitive input hints, masking on background and editor dismissal, masked reopening and cancellation without replacing the saved input. Password editor geometry is checked in both themes and densities in portrait and landscape. The full screenshot gallery includes masked and revealed password editors with sample text. `lifecycle.kosyncOpening` and `lifecycle.kosyncFinal` use a stalled loopback server to check blocked input, Cancel sync, the 0.5-second opening grace period, opening timeouts, final close/sleep deadlines, in-flight requests, wake cancellation and durable local progress. `session.reader-session` checks the opened book's binary and filename sync digests and retained filename identity and position imports, including an invalid position that leaves the book readable. Read-only sync descriptions resolve chapter and forward/backward source order without changing the local position or rendered frame.

`lifecycle.kosyncPasswordSleep` checks that sleep dismisses a revealed password editor and that reopening it after wake starts masked without the unfinished input.

The `timingEvents` desktop check verifies that these stages fit their totals. The `build.eval-device-outcomes` check verifies failed, skipped and missing device scenarios in both supported result formats, and a run that omits the device part.

## Main-thread guard

Normal diagnostics retain events in worker-written batches without a sync for an activity-only batch. A warning, an error or a lifecycle flush requests a sync. JSON serialization runs on the logging thread. Only detailed mode collects memory samples and expensive timing fields. The queue targets a maximum five-second delay while the writer is available; worker stalls, failed writes and power-loss durability have no such bound. Normal allowed-wait events report operations lasting at least 50 ms, with their reason and duration. Detailed mode reports all measured waits.

`src/support/main_thread.h` enforces the rule that a page turn never waits for storage. The reader registers itself as an interactive screen while a tap can turn the page. Each operation that writes storage or waits for another thread reports itself: profile database calls, synchronous record writes and flushes, JSON, bookmark, highlight, layout-cache, sleep-snapshot, dictionary and annotation-export files, and on Kobo, Nickel progress and reading-time writes. When such an operation runs on the main thread while the reader is interactive, that is a violation, unless an `AllowBlocking` scope names a reason. Sleep and host checkpoints are such scopes. Known exceptions, each marked with `AllowBlocking`: the Android and desktop library still saves, reads book progress and prepares an opening on the main thread, also while a book is open. On Android and desktop, the host checkpoint after a book opens waits on the main thread. On Kobo, opening attempts only a native status update under the loading view, before input is enabled. It does not save or read back position, percentage or estimates, and it does not retry. Firmware 4.46.23836 and 6.0.279225 status-update disassembly leaves `DateLastRead` untouched. Full native progress writes remain at lifecycle boundaries. A settings change, including a dictionary choice and a KOSync sign-in or account setting, waits for its write, so the caller can undo the change when the write fails. Annotation lists, the annotation editor and annotation export read saved rows on the main thread when the user opens them, and export writes its file there. The settings and annotation exceptions run when the user changes a setting or opens a panel, not on a page turn. The desktop and Android opening checkpoint can run while the user reads; it remains open work. The test executables check only work that runs inside event delivery, so a test can inspect saved data between events.

The reader also names these lifecycle scopes explicitly:

- `closing reader`: the reader is being destroyed and cannot accept input. Its destructor persists the informational KOSync timestamp and requests a diagnostic flush bounded to one second.
- `opening status before reader input`: the loading view still owns presentation. Nickel's interface-thread API attempts the status-only update once before the reader accepts input.
- `final native progress before storage handoff`: USB or shutdown has stopped reader input and drained pending storage work. Nickel's interface-thread API writes and verifies the final native progress before the handoff continues.

These scopes permit waits only at their lifecycle boundaries. They do not permit storage waits during reading. The opening status scope replaces the old native opening-progress write and its retries while reading.

The native tests run with `KOBALT_STRICT_MAIN_THREAD=1`, set by `platforms/desktop/run-test.cmake`. A violation aborts the test and names the operation. To list every violation with its call stack, run the tests with `KOBALT_STRICT_MAIN_THREAD=trace`, for example `KOBALT_STRICT_MAIN_THREAD=trace ctest --preset mac -R lifecycle --output-on-failure -V`. Trace mode logs each distinct stack once and lets the test continue. On Kobo, a violation adds one `main-thread-blocked` event per operation to the event log. `model.main-thread` checks the guard itself.

Diagnostic event writes run on their own thread. `flushDiagnostics()` waits for that worker and calls the main-thread guard; reader callers must be at a lifecycle boundary. Tests that read `events.jsonl` call it first.

## Temporary files and timing

Shared native fixtures verify their immutable staged asset bundle once when constructing reading-font inputs. Model matrices reuse those paths without retaining font bytes or open files. Desktop rows also reuse the placeholder font registration, while each profile supplies its own optional sideload directory. Asset mutation and recovery checks use separate bundles and retain production verification on every requested check.

All native checks and screenshot runs use private working and temporary directories under `build/desktop-mac/test-tmp/`. The CMake parent removes those directories after success, failure, signal termination or its timeout: 30 seconds for fast checks, 120 seconds for integration checks and 300 seconds for the full screenshot run. Regression children have a 90-second guard. CTest leaves five seconds after the launcher guard for cleanup. These process budgets detect hangs; they do not change per-action assertions or USB deadlines. Desktop fixtures drain the reader before removing their profiles. Screenshot staging stays inside the parent-owned temporary directory. If replacing a complete screenshot set fails and rollback also fails, the previous set remains outside that directory and the error names its location. Keep the current screenshot set, latest useful failure evidence and incremental caches.

Measure with `/usr/bin/time -p` around the commands above. Report the first build of restored targets separately from an unchanged build. A dependency recipe or patch change currently invalidates the complete dependency set; application-only changes reuse it. Do not compare different test inventories or SDKs as a measured speedup. Linux uses the same native targets and cleanup launcher through the `linux` presets; see [Linux builds](building.md#linux). Keep host and Qt version consistent when comparing timings or image checksums.
