# Storage compatibility

`disable_reader_standby` is an optional global Boolean. Missing or invalid values use false. True prevents automatic reader standby on supported Kobo hosts while the reader is visible and active. Explicit sleep, closing, USB export and shutdown retain their normal behavior. Other hosts preserve the preference but do not apply it. This keeps settings schema 1.

Kobalt separates saved reading data from disposable rendering caches. Storage formats are versioned independently of application releases. Hosts choose the storage directory; `storage::Paths` owns the shared filenames. JSON uses UTF-8. Writes use `QSaveFile` to replace a complete file atomically.

## Saved reading data

`chapter_groups` is an optional global string with values `current`, `all` and `off`. Missing or invalid values use Current section. The choice controls whether chapter groups can collapse and which groups open expanded. It does not change book layout, chapter statistics or reading positions. Settings schema 1 stays unchanged.

`reader-settings.json` holds global preferences with `schema: 1`. Unversioned settings are upgraded atomically. Recognized retired settings are converted or removed, invalid known values fall back to their defaults, and unknown keys are preserved. Unsupported future versions block writes until profile preparation moves them aside, as described in [Unusable saved data](#unusable-saved-data). `config.json` remains the small Kobo enable/disable configuration.

The retired `native_hide_status_bar` preference is removed when settings are normalized. The Mac screen preset controls status visibility. This keeps settings schema 1.

The retired `show_link_indicator` preference is ignored. Existing saved values remain in the settings record. Settings schema 1 stays unchanged.

`tappable_links` is an optional global setting with values `off`, `footnotes` and `all`. Missing or invalid values use Footnotes only. Saved choices are preserved. The value `off` is shown as Always require long press. It does not change the settings schema or parsed-book cache format.

`show_light_gesture_feedback` is an optional global Boolean. Missing or invalid values use true, preserving the existing brightness and warmth popup. False hides only the gesture popup and its cleanup refresh. `edge_light_gestures` still controls whether the gestures are enabled. Both choices persist independently for all books. Settings schema 1 and reading-data formats stay unchanged.

The retired `light_dark_mode_shortcut` preference is removed during normalization. Light always shows its Dark mode control on hosts with frontlight support. Dark mode remains available in Settings on every host. Settings schema 1 stays unchanged.

`disable_navigate`, `disable_stats`, `disable_annotations`, `disable_bookmarks` and `disable_kosync` are optional global Booleans. Missing or invalid values use false. The first four hide UI entry points; `disable_kosync` also stops KOSync activity. A hidden Navigate or Stats default menu view resets to None. Hiding Navigate resets its button action, hiding Stats resets Compact chapter graphs, and hiding annotations resets Minimal annotation mode. Hiding both bookmarks and annotations resets their shared sort order. Saved reading data, reading history, time estimates and sync credentials are retained. Settings schema 1 stays unchanged.

`turn_off_wifi_on_open` is an optional global Boolean for the Kobo Wi-Fi power saver. Missing or invalid values use false. False keeps Wi-Fi as Nickel leaves it when a book opens and at sleep. The key keeps its name; the setting is shown as Smart Wi-Fi power saving. The feature is not final until beta 7. Until then the settings cleanup (`cleanPreferences` in `src/reading/appearance_settings.cpp`) removes this key whenever settings are read or written, so Kobalt never saves it and the power saver stays off. This keeps settings schema 1.

`time_remaining_format` is an optional global string with values `detailed` and `approximate`. Missing or invalid values use Detailed. The choice controls the display of remaining-time estimates in the header, footer and Kobalt sleep screens. It does not change stored reading pace, book state or cache identity. Settings schema 1 stays unchanged.

`dictionary_font_face` and `dictionary_font_size` are optional global preferences. An empty or missing face follows the current book’s resolved body font, including its normal reading-font fallback. A missing size uses 100 percent. Supported sizes are 80, 100, 120 and 140 percent. Invalid values use these defaults. These settings affect dictionary definition text, not book layout or saved annotations. They keep preference schema 1.

Dictionary-to-book search uses the current lookup term in memory. It adds no saved preferences or book fields and changes no storage or cache format.

`vertical_justification` is an optional global setting with values `off`, `expand` and `center`. Missing or invalid values use `off`. The Boolean used by early development builds maps to `expand` or `off`. `vertical_spacing_scope` selects `all` or `protection`; missing or invalid values use `all`. These fields keep settings schema 1 and canonical reading positions. Parsed-book cache format 6 stores source line boxes and whether a page gap was caused by widow/orphan protection. Older rendering caches rebuild without changing saved reading data.

`hanging_punctuation` is an optional global Boolean. Missing or invalid values use false. It lets punctuation and line-ending hyphens extend into available margins, including the gap between two columns. Global values replace stale book snapshots and do not follow typography inheritance. It participates in appearance identity and preview snapshots. Settings schema 1, book-record format 1 and the parsed-book cache format stay unchanged.

Book state now lives in `kobalt.sqlite`. Legacy book state uses a host-selected prefix followed by the SHA-256 of the UTF-8 book identity and `.json`. Its `schema` is `1`. The `book` and `fingerprint` fields identify the publication. It stores the canonical reading position, book-specific text preferences and native progress reconciliation fields. Globally owned layout preferences remain in global settings. Marking a book unread resets its position and book-specific preferences, but keeps annotations. Reopening a finished book resets only its reading position and finished status. It preserves book-specific preferences and annotations, using the existing checkpoint format.

`image_views` is an optional book-state array. Each entry stores an image content SHA-256 ID, `zoom` from 1 to 8 and normalized image-center coordinates `x` and `y` from 0 to 1. Missing or invalid entries use Fit. Content IDs are computed from the decoded image dimensions and opaque pixels on the engine worker, so reflow and repeated references keep the same ID. The views belong to the book and survive reopening. Changed image content gets a new ID. Fit removes that image's entry. The reader retains up to 64 recently adjusted views and drops the oldest entries if needed to keep a reading-position checkpoint within its existing byte limit. Saves use the background book checkpoint writer. Book-record format 1, legacy JSON schema 1 and database schema 3 stay unchanged. Older builds do not apply these views. Their preservation depends on that build’s book-state handling.

`suppress_finish_prompt` is an optional book-state Boolean. Missing or invalid values use false. True suppresses only that book’s finish prompt. It uses the existing publication identity and checkpoint writer, and survives reopening and restarting. Mark as unread clears it with other book-specific settings. Book-record format 1, legacy JSON schema 1 and database schema 3 stay unchanged. Reading positions, annotations and preferences keep their existing meaning.

Legacy JSON bookmarks and annotations share `annotations/<book-key>/`. `book.json` has `version: 1`, `identity`, `title` and `fingerprint`. Book keys come from `BookmarkStore::bookKey`: native book identities remain stable across downloads; sideloaded books use their content fingerprint. A changed file can adopt annotations from the previous record of the same path.

`bookmarks.json` has `version: 1` and a `bookmarks` array. Each bookmark stores `position`, `chapter`, `excerpt` and `created`. Positions are canonical CREngine XPointers, not page numbers. Dates are UTC ISO 8601 strings.

Bookmarks support optional `name` and `icon` strings, limited to 128 and 64 UTF-16 code units. Missing fields mean an ordinary bookmark. A nonempty icon pins the bookmark; each book permits eight pins. Unknown icon tokens retain their stored value and display a star. Pinned bookmarks retain their exact anchors when reflow places several bookmarks on one page. Ordinary bookmarks still merge.

SQLite stores pin metadata in a format-1 `profile_state` record named `bookmark-pins:<book-key>`, keyed by the bookmark row ID. The bookmark transaction reads and writes this bounded record with the list and uses the list revision for stale-writer protection. A failed pin write rolls back the entire bookmark edit. Import and changed-file adoption preserve pins. The optional record keeps database schema 3 and bookmark JSON format 1. Older builds do not display or maintain pins; writing a profile with an older build is not a supported way to edit pinned bookmarks.

`highlights.json` has `version: 1` and a `highlights` array. Each entry stores `id`, `start`, `end`, `text`, `chapter` and `created`. Optional `color` defaults to `gray`; optional `style` defaults to `shaded`. Supported styles are `shaded`, `underline` and `dotted`. Unknown color and style tokens survive edits and use a display fallback. Optional `sentence_start` and `sentence_end` objects preserve endpoint provenance through `enabled` and `chosen_start` or `chosen_end`.

An optional `note` string holds plain text for a future note editor. Missing notes mean empty text. Notes preserve Unicode and line breaks and are limited to 65,536 UTF-16 code units. Passage edits and appearance changes preserve the note. Beta 4 does not expose a note editor. Adding this optional field does not change format version 1.

Each book supports up to 2,000 bookmarks and 2,000 annotations. Bookmark files are limited to 1 MiB and highlight files to 8 MiB. An annotation excerpt is limited to 262,144 UTF-16 code units. Malformed or unsupported annotation files block subsequent saves rather than replacing the original data with an empty list.

The diagnostic JSON bookmark backend rejects the complete list when any row has an invalid position or the list exceeds its count limit. It does not keep a partial list. A failed load or changed-file adoption blocks saves and preserves the original bytes. SQLite imports retain their version, schema and full-list checks.

Add compatible optional fields within version 1. A change to required fields, their meaning or location needs an explicit format version and migration. Do not tie data versions to release names. This is the current format contract, not a promise that older builds preserve arbitrary unknown fields. Book-state imports reject unsupported schemas without replacing the source. Database record formats are versioned separately and unsupported formats block updates.

`button_actions` is an optional global object in settings schema 1. Stable physical control IDs map to `previous`, `next` or `none`. Missing and invalid actions use the host's native direction. Unknown control IDs and values remain in the object when a known button is edited, so a profile can move between hardware layouts without losing its other mappings. No book data or cache format changes.

`header_footer` also accepts `phone`. The Phone preset has no header and retains the usual chapter-pages-left and book-percentage footer. It is offered on phone screens, whose short edge is under 3.4 inches, and is the default only when no header/footer choice, legacy setting, custom layout or text sizing has been saved. Explicit choices survive device detection and rotation. This keeps settings schema 1 and book-record format 1. Older builds do not recognize `phone` and can use their default preset when loading it.

Header/footer Custom slots also accept `battery_percent_only` for a percentage without an icon. The existing `battery_percent` value keeps its icon and percentage. Missing slot values keep the fallback layout. Settings schema 1 is unchanged. Older builds do not recognize the new choice and can replace it with their fallback when saving.

`header_footer_text` is an optional global object that separates header/footer sizes and Off states from preset content. It uses `header_size`, `footer_size`, `header_font_size` and `footer_font_size` with the rules below. Missing or invalid values fall back to the selected legacy layout. The first preset or size edit saves the current sizes independently. Preset changes then preserve them; sizing does not overwrite Custom. This keeps settings schema 1.

The sleep screen defaults to book cover with Bookmark. A one-time cleanup changes an old `sleep_screen` value of `stock` to `cover` and records `sleep_defaults_migrated` so a later explicit choice of Kobo's screen survives. Existing cover and reading-page choices stay. The removed `band` style falls back to Bookmark, and an explicit Card stays. The `none` style omits the indicator. The new `overlay` mode reads the user's PNG files separately from saved preferences. The settings schema remains 1.

Header/footer Custom layouts retain the legacy `header_size` and `footer_size` strings. The optional integer fields `header_font_size` and `footer_font_size` store a size from 24 to 48 in 300 PPI pixels for both strips. Missing or invalid numeric fields use the legacy Small, Medium or Large value (24, 26 or 28). Off disables the strip but retains its numeric size. Saving also writes a legacy size, or Off, for older readers. Older builds can fall back to those choices but are not guaranteed to preserve the optional numeric fields when saving. These optional fields keep settings schema 1 and do not change book positions or annotations.

`paragraph_spacing` is an optional global integer. `-1` or a missing or invalid value keeps Publisher spacing. Values from 0 to 200 replace ordinary paragraph gaps with that percentage of the text size. The global preference overrides stale book values and does not follow text inheritance. It keeps book-record format 1, settings schema 1 and database schema 3. Parsed-book cache format 7 adds paragraph markers so cached books can apply the control without reparsing. Older rendering caches rebuild without changing reading positions or annotations.

`paragraph_indent` is an independent optional global integer. `-1` or a missing or invalid value keeps Publisher indentation. Values from 0 to 300 replace the first-line indent on marked ordinary paragraphs with that percentage of the text size. Zero removes indentation. Global precedence and text-inheritance exclusion follow paragraph spacing. The field keeps saved-data versions and parsed-book cache format 7; it uses the same paragraph markers.

`beautifier_initials`, `beautifier_spacing` and `beautifier_indent` are optional global Booleans, default false. Each checked rule applies directly. Invalid values load as false. The earlier `book_beautifier` master switch is removed during preference normalization: disabled converts to all rules off; enabled preserves selected rules, defaulting missing legacy rules to on. Global values replace stale per-book snapshots on opening, including values from the earlier per-book prototype. These fields are excluded from typography inheritance. The saved-data formats stay unchanged. Parsed-book cache format 9 is unchanged. New parses mark text initials independently of paragraph classification, including generic floated initials and CSS first letters, without changing source text or IDs. Existing cached books retain their earlier markers until their disposable cache is rebuilt. The mode participates in appearance identity and preview snapshots.

`normalize_page_margins` and `reduce_chapter_spacing` are optional global Booleans, default true. They split the retired `avoid_wasteful_styling` setting. Migration copies its value to each missing rule and removes the retired key. The existing three `beautifier_*` rules keep their defaults and values. `book_normalization_preset` records `recommended`, `full` or `custom`. Recommended enables only the two spacing rules; Full enables every rule. Existing combinations select their matching preset or Custom. An explicit Custom remains Custom even when its rules match a preset. Global rules replace stale book snapshots and are excluded from text inheritance. Settings schema 1, book-record format 1 and parsed-book cache format 9 stay unchanged. The rules change rendering styles without changing parser markers, source text or reading anchors.

## Sync account

`kosync.json` stores the optional sync account separately from book data and rendering caches. Its schema is 1. It holds the HTTPS server URL, username, password-derived MD5 authentication key, persistent device ID and automatic-sync preference. The optional `last_sync` field stores the last successful progress exchange for this account on this device as a UTC ISO 8601 timestamp. Missing or invalid timestamps mean no recorded sync. Changing the server or username clears the timestamp. Successful exchanges update this date in memory. Sleep and closing the book persist it, including closes for USB and power-off. A sync that ends while the device sleeps, such as the sleep sync, queues its own write and does not wait for it. Sleep writes nothing when no exchange succeeded since the last write. Account and settings changes also persist it. A crash can lose the informational date. A deferred date write preserves newer account settings and refuses to restore a removed or changed account. Failed and cancelled exchanges do not update it. The optional `device_name` field is a custom display name, limited to 128 UTF-16 code units without control characters. Missing or empty names use the platform-detected default. Renaming preserves the device ID and last-sync timestamp. The optional `match_method` field is `binary` or `filename`. Missing values use `binary`. Unsupported values block writes. Changing this preference clears the last-sync timestamp but preserves the account and device identity. The optional Boolean `manual_explanation` defaults to true when missing or invalid. Confirming the toolbar explanation sets it to false. Account edits preserve it without changing schema 1. The optional integer `sync_interval_minutes` sets how often an open book syncs a changed position: 0 for every page, 1, 5, 15, 30 or 60 for minutes, or -1 for never. The optional Boolean `wake_wifi` allows those periodic syncs to turn on Wi-Fi. The optional Booleans `sync_on_open`, `sync_on_sleep_wake` and `sync_on_close` turn each of those moments on or off. Missing or invalid values use 15, false and true, and do not block writes. Accounts saved before these fields existed therefore sync every 15 minutes while reading, where they synced after every page before. Account edits preserve these fields without changing schema 1. The plaintext password is never stored. The key grants account access. Writes are atomic and request owner-only permissions where the filesystem supports them. Kobo's FAT-backed profile remains accessible over USB. This is a profile credential file, not an operating-system credential vault. Signing out clears the key. Missing files mean signed out with no server URL. An empty server URL is valid only for a signed-out account. Invalid or unsupported files block writes and are preserved. Profile preparation moves a file that is not valid JSON or has an unsupported `schema` into `backups/`. Optional fields survive account edits. Copying this file also copies its device identity, so set up each device by signing in separately.

On Android, private `book-filenames` SharedPreferences retain the source display name for imported and cached books. Filename matching uses this name instead of the internal hashed filename. Earlier imported books need to be imported again to supply this metadata. Missing source names disable filename matching for that book without affecting binary matching.

## SQLite profile database

Beta 4 uses SQLite by default for bookmarks, annotations, book state, the standalone Library catalogue, recent-book metadata and aggregate reading speed. Global settings remain JSON. Set `KOBALT_ANNOTATIONS_SQLITE=0` to select the legacy JSON backend for diagnostics, or configure a diagnostic build with `-DKOBALT_SQLITE_ANNOTATIONS_DEFAULT=OFF`. An explicit environment value of `1` selects SQLite even in that build. Backend selection is captured when each store is constructed. Do not switch backends while a book is open.

The database is `kobalt.sqlite`, directly in the profile directory alongside `reader-settings.json`, outside the rendering cache. Legacy JSON sources originate under `annotations/`; profile preparation archives completed imports under `migration-backup/annotations/`. It has application ID `KAN1`, UTF-8 database encoding and schema version 3 in `PRAGMA user_version`. This version is independent of the JSON format version and application release. Opening checks the encoding before any persistent configuration change and rejects other encodings without converting them. Stored strings use explicit UTF-8 byte binding and are selected as bytes for decoding with an explicit length. This preserves embedded NUL characters and literal leading U+FEFF characters across Qt providers. Unknown, foreign or damaged databases are rejected without recreating their schema. Profile preparation then moves them into `backups/`. Future incompatible schemas need explicit transactional migrations before their version changes.

The first opening imports a book's bookmarks and highlights in one transaction. Beta 3 has version-1 bookmarks and no highlight file. Later version-1 highlights can include colors, styles, endpoint provenance and notes. Imports preserve those fields, IDs, timestamps and record order. They keep the original JSON files unchanged. An interrupted import can retry without duplicating records. Invalid or unsupported source data blocks the import instead of silently discarding it. Fingerprint adoption checks committed database records and unmigrated JSON sources; retained JSON from an already imported book does not replace newer database edits.

After import, SQLite is the authoritative store for that book. The retained JSON files are import snapshots, not current exports. An older application can edit those snapshots without updating SQLite. Reinstalling an older build is therefore not a supported way to transfer new database edits back to JSON; that needs an explicit compatible export and conflict handling.

The annotation format permits gaps in stored order values. The upgrade path imports Beta 3 and current JSON records into this database. Negative, non-integer and duplicate order values are rejected. Deleting an entry preserves every surviving order value; appending assigns the next value. Explicit reordering, insertion before an existing entry or exhausting the signed 64-bit range can assign a new sequence.

Each load reads its metadata, payload bounds and records from one transaction snapshot. Each save changes only added, modified, removed or reordered rows. A per-list revision rejects stale writers. A failed transaction preserves the prior saved list, and the session restores its in-memory list. The database keeps the existing per-book count and encoded-size limits. It requests a 2 MiB page cache and disables memory mapping. The cache setting is not a total process memory limit.

The reader can load compact highlight records with IDs, endpoints, provenance, appearance and timestamps. Compact records do not retain excerpts, chapter labels or notes. A visible-list request reads only its requested excerpts and chapter labels. Opening an individual record for editing reads its complete details. Both requests use the revision of the compact list and reject a concurrent change. The ordinary full-load API and JSON backend keep their existing behavior.

Compact loading checks SQL field-byte bounds, metadata, IDs, count, ordinal order and stored byte totals. It also rejects a payload whose raw byte lengths exceed its stored encoded size. It does not recompute the exact JSON-equivalent size or UTF-16 validity of unloaded payloads. Excerpt requests validate the fetched text and chapter limits; complete detail requests validate every field and recompute the exact encoded row size. This deferred validation means a damaged unloaded payload can remain undiscovered until requested. A compact appearance edit reads and validates that row's full details within the write transaction before preserving its excerpt and note. Endpoint edits require complete details. Deletion does not read the deleted payload. Successful compact saves discard loaded payloads again, and read-only detail requests do not populate the store's retained records.

## Profile connection

One writer thread owns `kobalt.sqlite`. Every read and write runs on that thread, one at a time, through one connection. No other code opens the file while that connection is open. Operations from other threads wait for their turn; calls that a caller waits for run before waiting background writes, but a background write that has waited two seconds runs next. Only Kobalt writes this file.

The connection takes an exclusive lock before its first read and keeps it until it closes. It uses write-ahead logging: a commit appends to `kobalt.sqlite-wal`, and a checkpoint folds the log into the main file. With the exclusive lock, SQLite keeps the log index in memory and creates no `-shm` file. Commits use `synchronous=FULL`, which syncs the log. Periodic reading activity and immediate bookmark, highlight and progress-choice writes use `synchronous=NORMAL`. These commits do not request an additional per-commit sync; a synced commit or a checkpoint makes earlier commits durable. SQLite automatic checkpoints remain enabled and can sync during reading. A crash of the process loses no completed commit, but loses pending application memory. A power loss can lose routine saves that were not yet synced, but not a synced commit, and it does not corrupt the database. If SQLite refuses write-ahead logging, the connection keeps a DELETE rollback journal with `synchronous=EXTRA`.

Opening checks ownership, version, encoding, page size, column names, order, types and primary keys in all eight tables before its first change to the file, the switch to write-ahead logging. It also runs SQLite integrity and foreign-key checks before that switch. A rejected file keeps its content; only a log left by a crash is folded into it. Opening also refuses a read-only file, so no connection stays open that cannot write.

The connection checkpoints at sleep. Ordinary standby does not force a reading batch or a profile checkpoint. At 5% battery or below, while not charging, eligible activity makes a durable batch due after one minute, and standby first queues dirty reading data and a durability checkpoint. The reader uses the existing battery observation; it adds no battery poll. After a failed checkpoint, standby waits five minutes before it asks for another. Failed batches also retain their data through a five-minute retry cooldown. These cooldowns do not block standby. It closes when a book closes, after the reader is disposed for a transition, at USB export and at power-off. Closing waits for waiting writes, checkpoints, returns the file to a DELETE rollback journal and closes it. A copy, a computer over USB and older builds then see one ordinary file. After the close at USB export and at power-off, every operation fails until the partition is mounted again or the USB connection ends before the export. Only the current USB request can close and block the profile after its reader drain. A cancelled drain cannot block it again, and unplugging cannot reopen it during power-off. The firmware unmounts the partition lazily before export and freezes Nickel at power-off, so no file may stay open then. The first operation after a close opens the file again.

A process that ends without closing leaves `kobalt.sqlite-wal`. The log belongs to the database. Preserve it with the matching main file until recovery completes. Copy that file set only while the writer is stopped; never discard the log to clear a lock. The next opening replays it. Earlier builds also replay it when they open the file, and return it to a DELETE rollback journal.

Book state, bookmark, highlight and reading-speed writes are background writes. Each owner keeps at most one waiting write; a newer write of the same record replaces it. While reading, position, history and speed stay in memory until a batch becomes due five minutes after the last successful batch. The next eligible activity queues one immutable snapshot in one SQLite transaction. Page turns, jumps and layout changes use this schedule. There is no periodic save timer. Each failed batch gets at most three short attempts, then a five-minute cooldown; eligible activity retries it after that cooldown. Failed writes never advance the last-success time. Layout memory saves separately and durably on the writer thread when appearance changes. A failed appearance save gets at most three short attempts, then retains the latest snapshot through a five-minute cooldown. New edits replace that snapshot without restarting the retry budget. A due activity batch retries it after cooldown; page turns do not retry it directly. Synchronous and close checkpoints can save appearance during cooldown. Sleep and host checkpoints wait for their save and durability result. USB, close and power-off drain queued work before releasing storage, including a durability checkpoint when the newest values are unchanged. Manual transition failures offer Retry or quit without saving after three attempts. Battery-low shutdown makes the same bounded attempt, drains active storage work, logs failure and proceeds without a dialog. An in-flight write cannot be abandoned safely merely because a deadline expired. Bookmark and highlight edits show at once. When the newest save fails, the session restores the last saved list and reports the error. USB export and power-off wait for waiting annotation writes. A process crash can lose the pending activity batch. Inactivity and repeated failures can make that batch older than five minutes. Power loss can also roll back committed NORMAL transactions that have not been synced. Neither loss has a strict five-minute bound. Saved data must stay outside `.cache/` even when the database schema changes.

The connection sets `max_page_count` from the database page size to keep the main file below FAT32's 4 GiB per-file limit. This does not bound the log or journal size or guarantee free disk space. SQLite's automatic checkpoint folds the log into the main file after about 1000 pages. A database already larger than that limit is rejected without changing its contents. Initial schema creation uses a temporary sibling file and an initialization lock. The complete database is published by rename, followed by a directory sync; an unpublished staging file does not block a later retry.

## Backups and external database access

Exclusive ownership is part of the storage contract. Another SQLite connection cannot inspect or back up the profile while its writer connection holds the lock. This includes read-only connections and SQLite's backup API. A connection's busy timeout does not necessarily bound a backup API's retry loop. Increasing an external tool's deadline does not release the lock.

For an ordinary backup, stop the application or complete its storage handoff before copying. Wait for pending writes and the writer connection to close, then prevent any operation from reopening the profile until the copy finishes. A quiet interface, an idle writer or a completed checkpoint is not a backup barrier. Closing a book alone does not reserve the file against later database operations.

Copying only the main file while the writer is active can omit committed WAL data. Copying the main file and WAL separately while writes or checkpoints continue can mix different states. If a log remains after a crash or failed close, preserve the complete file set while the writer is stopped. Recover and verify an isolated copy before using it; never repair or checkpoint the original as part of inspection.

An online backup feature must coordinate through the profile writer. It needs a consistent snapshot and explicit completion before it releases ownership or resumes writes. External tools must not bypass the exclusive lock or open the running profile directly. Diagnostic snapshots are separate from an application backup API: they must stop file changes during capture, retain the required journal files, recover only the copy and verify its integrity before querying it.

## Reading sessions

Android, desktop and Kobo record foreground reading intervals in `reading_sessions`. Each row has a UUID, annotation-compatible book key, reading identity, content fingerprint, source key, title and author snapshot, start and last-observed UTC timestamps in milliseconds, active milliseconds, canonical start and end positions, and an `active`, `completed` or `interrupted` status. Metadata and positions are limited to 4,096 UTF-16 code units each. Text bindings preserve Unicode and embedded NUL characters. Android folder books retain their original document-provider key as well as the cached reader identity. Indexes cover book/start time and start time. History has no foreign key to annotations or the Library catalogue, so removing a book or marking it unread preserves its sessions. Matching content fingerprints share a book key; changed editions remain distinct.

The existing monotonic reading timer supplies duration. UTC timestamps provide chronology and never reduce within an interval if the clock moves backward. A session starts only when a usable reading page is shown. Sleep or app suspension stops the active clock and saves the session without completing it. Settings → System → New session after sleep selects 15 minutes (default), 1 hour, 4 hours, 6 hours, 12 hours or Never. On returning to a usable reading page after at least that much wall-clock time, the previous session is completed at its last pre-sleep observation and a new UUID begins. The displayed session timer resets with the new UUID. Shorter sleeps retain the UUID and timer; sleep time is never added to active duration. Repeated sleep or checkpoint notifications retain the original sleep boundary. A backward wall-clock adjustment does not expire the session. Hiding an otherwise active reader, closing the book, USB handoff and shutdown complete the session, including a retained sleeping session. A host checkpoint while suspended stops the clock before saving, even if the host callback runs before the reader callback. Foreground reading menus count toward duration, as they do for the existing session timer; pace training can pause independently. There is no inactivity timeout based on page turns.

The reader retains new intervals and their updates in memory until the activity batch or a commit point. An immutable snapshot joins position and speed in one SQLite transaction. Pause and close stop the clock before saving. There is no separate history timer. Each save writes an absolute duration under the same UUID. Failed transactions keep pending intervals for retry while the book remains alive. Repeated failures followed by process termination can still lose unsaved time. Before its first book opening, the reader host acquires profile ownership through `.reading-history.lock` and recovers unfinished intervals. Controllers in one app process share the same owner, so creating another controller cannot interrupt a live session. Another process cannot start a reader for that profile while the owner remains alive. Different profile directories are independent. Ownership uses an OS file lock, released automatically when the process dies. The marker is a persistent inode, not a PID record; an empty file or a crash during marker creation does not block the next owner. Do not unlink it while an app owns the profile. Failed recovery releases ownership so a later opening can retry. Recovery marks them interrupted at their last committed observation and counts no downtime. A sudden termination can lose time since the last successful checkpoint. Existing aggregate pace samples cannot reconstruct earlier sessions, so migration creates no historical rows.

Kobo writes the same history alongside Nickel reading-session reporting. Nickel still receives separate active intervals so its reading time excludes sleep. The timeout groups Kobalt history and resets Kobalt’s session timer. It keeps Nickel’s reading-time estimates. History ownership is retained across ordinary book closes and released after the storage drain before USB export or power-off. The next opening reacquires ownership and recovers interrupted intervals. The legacy JSON diagnostic backend does not record sessions. Session recording does not change the book-state JSON format, preferences format or rendering caches. Stats does not display historical sessions yet.

## Annotation exports

Annotation exports are compressed ZIP snapshots for reading outside Kobalt. Each archive contains one selected UTF-8 file: `annotations.md` or `annotations.html`. Both documents group consecutive chapter labels in source order, label entries as annotation numbers and omit page numbers. HTML uses compact `#1`, `#2` links and renders the saved marker, solid underline or dotted underline in the reader’s color palette. Unknown styles and colors use the same display fallbacks as the reader. The app embeds bundled Libron Regular as a base64 font for passages, with a non-visible HTML comment referencing the SIL Open Font License (OFL) 1.1. Missing font assets leave a system-serif fallback. Each entry includes its creation timestamp. Markdown shows UTC explicitly. HTML starts with UTC fallback text and formats timestamps in the browser’s locale and timezone when JavaScript runs. HTML has embedded styles, search and Book order, Newest first and Oldest first sorting. Date sorts use the original instants, with source order as the tie-breaker, and keep annotation numbers unchanged. The HTML needs no external files, network requests or browser storage, including when opened from a `file:` URL. The Nickel integration writes them under `/mnt/onboard/Kobalt/Annotations/`. Mac and Android use Qt's native save picker to select a filename and location. Export fetches complete saved records in one revision-checked request, including notes omitted by compact loading. Export requires a confirmation naming the book and ZIP contents. It hydrates and sorts the snapshot using resolved source positions, then builds the archive before opening the picker. Kobo requires a distinct Replace ZIP approval for an existing destination and checks again before writing if a file appeared during the initial confirmation. The native picker keeps overwrite confirmation enabled on other platforms. Exports wait for the annotation list’s location lookup; unresolved passages sort after resolved passages in their saved order. Suggested filenames combine a sanitized title and the first 16 hexadecimal characters of the SHA-256 book identity, followed by `-markdown.zip` or `-html.zip`. The two formats never share a default destination. Local destinations use `QSaveFile`, which replaces an existing export only after the complete snapshot is written. Android `content:` destinations use the picker-granted access and a direct `QFile` write; atomic replacement depends on the document provider. Cancelling the picker writes nothing. Exports are not backups for importing annotations, do not change saved-data versions and do not modify Nickel settings. The checked Show annotation styling option below search hides or restores marker fills and underlines. It keeps passages, notes and the embedded font visible, and applies to printing.

## Disposable caches

Parsed-book cache format 10 rebuilds paragraph markers for publisher containers with zero-width borders. These containers now allow ordinary paragraph adjustments. Visible borders keep their protection. Older rendering caches rebuild without changing settings, reading positions or annotations.

Parsed-book cache format 11 rebuilds books under the embedded font size limit. Older rendering caches rebuild without changing settings, reading positions or annotations.

`.cache/` belongs exclusively to CREngine. Never put settings or annotations there: the engine removes files it does not recognize. It stores parsed books in an engine-specific binary format, with a 128 MiB budget. It is not an interchange or backup format.

The parsed-book checksum retains the beta 7 compatibility token, the explicit Kobalt parser format and the requested DOM version. Dependency revisions, build recipes and patch checksums do not change it. Review upstream and local patches before declaring an update compatible. Bump the format in `documentCacheChecksum` when parser or preprocessing changes make the cached DOM unsafe to reuse. CREngine also rejects incompatible engine cache formats. Density, user CSS and bold-reading variants keep their existing checks.

Rendering compatibility is separate. Increment `rendering_version` in `platforms/cache-policy.cmake` for shaping or layout changes not covered by CREngine's formatting version. The rendering policy also includes bundled hyphenation pattern names and contents. A cache with an older or missing rendering policy keeps its parsed DOM and Kobalt markers, then rebuilds styles and pagination once. Saving records the current policy in that cache; the next unchanged opening reuses its layout. The engine dependency update after beta 7 uses this path. Settings, reading positions, bookmarks and annotations are not cache data and do not change.

Decorative page-spacing records retain prose-gap boundaries and the fixed opening prefix for disk-cache reopening and alternate viewport snapshots. Eligibility is computed during layout without adding DOM markers. Changes to these records require review of both engine-format and rendering compatibility.

An open book can retain one alternate viewport layout in memory. The snapshot holds node geometry, immutable styles and serialized page boundaries. It shares the publication DOM and resources and resolves fonts through the existing engine cache-loading path. It does not retain another engine or page images. Each snapshot has a 4 MiB budget for its records, page buffer and retained styles. A swap can temporarily hold two snapshots. Larger layouts and changes to the document tree use normal pagination. Closing the document or releasing an idle book discards the snapshot.

These snapshots belong to one live document and parser instance. Reuse requires the exact viewport dimensions, column count and column spacing. Typography, layout settings, user CSS and reading-density changes discard them. Opening another publication creates another document. Parser, engine and font inputs cannot cross document lifetimes through this memory cache. The font manager refuses a different font input set while documents are alive. The existing disk cache still stores the latest document layout; snapshots do not serialize extra disk variants or add a persistent format. CREngine can still page its existing document storage on the worker. Saved-data versions and the parser format stay unchanged. A change to these layout records requires a rendering-version review.

The engine's render context includes the side allowances that each paragraph can use for hanging punctuation and glyph overflow. Two columns with hanging punctuation have a larger allowance than one column, and margins and column spacing change it without changing the text width. A disk-cached or retained layout made with the same allowance is reused, including a cached two-column opening and a rotation back to a retained layout. A layout made with another allowance is laid out again. The rendering version controls whether earlier cached geometry must be laid out again. Settings, reading positions, bookmarks and annotations stay unchanged, and the parser format stays at 10.

`cache/reopen-layout.json` is a separate bounded, version-1 cache of publication inspection results. Its policy follows the build's layout policy. It can be discarded without losing reading data. Bump its format version when inspection verdict rules change incompatibly, independently of the parsed-document format.

`cache/sleep-screen.png` is a disposable Kobo power-screen backdrop saved when a Kobalt book closes or completes its final USB save. PNG metadata version 1 stores the last-read record token, selected mode, orientation, progress, remaining-time text, theme and whether the page needs dimming. It also stores the percentage read. Images saved without it still load; the styles that draw it then leave it out. PNG writes use lossless zlib level 1 through the option supported by the installed Qt PNG handler. Existing PNGs remain readable. The status tile is composed when the device sleeps or turns off, in the style selected at that time. The file is replaced atomically and is limited to 20 MiB and 4,194,304 pixels.

When the native `N3_FULL` cover supplied the reader's decoded cover, `cache/sleep-screen.json` can replace the PNG. This disposable reference uses version 1 and kind `native-cover`. It stores the same display metadata and token, the viewport dimensions, and the cover's absolute path, byte size and modification time. The source identity is captured around the successful native-cover decode. Saving rechecks its attributes and image dimensions without decoding it again. Loading checks them again, bounds the source to 20 MiB and 4,194,304 pixels, and fits it to the saved viewport. Transparent cover pixels are flattened on white, as in the engine. The JSON is limited to 16 KiB. An absent or unusable native source at save time uses the captured PNG instead. A missing, changed, damaged or unsupported reference at load time uses Kobo's built-in screen. A present reference takes precedence over a PNG; a rejected reference does not expose an older PNG. A successful save removes the other cache form.

The last-read token is queried through an independent read-only database connection, so it sees committed data. The close-time query and persistence share a worker, which finishes before USB export or power-off. Home sleep still checks the current last-read token and rejects ties before using a retained in-memory backdrop or reading the cache. Native reference attributes are also rechecked before memory reuse. Opening another book removes both cache forms and the retained backdrop. These caches are separate from CREngine's `.cache/` and contain no authoritative reading data.

## Profile migration and cleanup

SQLite schema version 3 includes annotations, JSON profile records, the Library catalogue and reading sessions. Version 2 upgrades in one transaction after its existing columns, primary keys and referential integrity are checked. The transaction adds the session table and indexes, then advances `user_version`. Failure rolls back the upgrade. Beta 3 and supported version-1 JSON data import directly into version 3. Other versions and partial schemas are rejected without repairing or replacing the database. Initial database publication includes every table. Older builds that support only version 2 cannot open an upgraded profile.

`book_state(identity, format, revision, payload)` stores one JSON object per publication identity. Its encoded payload is limited to 16 KiB. `profile_state(name, format, revision, payload)` stores application records such as reading speed and recent-book metadata. Recent-book metadata permits 256 KiB; other callers retain the 16 KiB limit. Payloads use compact UTF-8 JSON, checked in the application without SQLite JSON extensions. The record format remains 1, independently of the database schema. Unsupported record formats and malformed or oversized payloads block updates. Optional fields, nested values, Unicode and embedded NUL characters survive JSON import and edits.

Unchanged checkpoints do not write their row. A changed checkpoint retains extra fields from the supported book record loaded at opening and replaces reader-owned values. Clearing a dictionary choice removes its field. Display-only fields, including chapter titles, page counts, current and next page numbers, resolved display font and cached-page counts, are excluded from saved checkpoints and removed from older records at the next save. Diagnostic state snapshots still include these fields. These changes keep record format 1 and database schema version 3.

A changed checkpoint replaces only that book’s JSON object and increments its revision in the same transaction. The revision counts changes; it is not a stale-writer token in the current checkpoint API. Reading positions, text overrides, dictionary choices and native progress reconciliation retain their existing meaning. Mark as unread replaces the book record with an identity-only checkpoint. A later opening does not restore the removed fields. Bookmarks and annotations remain in their indexed tables and are not included in this JSON object.

`library_books` stores one row per discovered book, including its source key, folder, metadata, cover filename, timestamps, progress and explicit read status. `library_folders` stores folder keys, labels and display order. Library view, sort and filter preferences live under `library` in `reader-settings.json`. Saving an unchanged book does not rewrite its catalogue row. Kobo continues to use its native library rather than these tables.

`imports(source, digest, record)` records successful JSON imports inside their data transaction. A retry uses the committed database record, never stale JSON. After commit, the original source is moved into `migration-backup/`. Its digest is checked before the move. A failed move can retry without importing twice. Book state and annotations from Beta 3 and current version-1 JSON sources are supported. Library migration rejects duplicate identities, missing folders and unsupported versions rather than dropping records. A failed Library import blocks catalogue saves and shows an error instead of creating a replacement empty catalogue.

Profile preparation imports recognized hashed book-state files and annotation folders, including books not reopened after the upgrade. On Kobo it runs at the first reading request, after the loading view paints, rather than during native startup and library initialization. Annotation imports retain source timestamps so a changed sideloaded book adopts the newest saved edition rather than whichever folder was migrated last. Imported annotation folders and their derived path index move under `migration-backup/annotations/`. Unknown files, symbolic links, malformed sources and unsupported formats are left untouched. Keep the migration backup until the upgrade has been validated. It is a historical snapshot, not a current downgrade export. Do not install an older build expecting it to read subsequent SQLite edits.

The old root inspection cache moves to `cache/reopen-layout.json`. Parsed engine books remain exclusively under `.cache/`. Existing inspection reports and bounded logs move under `migration-backup/diagnostics/`, so they cannot replace a new session’s diagnostic output. Kobo always writes the bounded event log in `diagnostics/` and crash reports in `crash-reporting/`. It writes new inspection reports only when `KOBALT_DIAGNOSTICS=1` or a `diagnostics-enabled` file exists in the profile. These files are not reading data. The standalone `active-session.json` and `startup-session` safety markers keep their recovery behavior.

## Unusable saved data

Profile preparation checks the saved data before anything else uses it. On Kobo it runs when the first book opens. On Android and desktop it runs when the reader controller starts, and again before a book opens if the storage failed.

`reader-settings.json` and `kosync.json` are unusable when they are not valid JSON, are larger than 16 KiB or have a `schema` other than 1. Settings without a `schema` are older settings. Kobalt upgrades them and does not move them. `kobalt.sqlite` is unusable when it has Kobalt's application ID and a version this build does not support, or when it is damaged, empty, foreign or uses another text encoding. A lock or an I/O error does not make the database unusable.

Kobalt moves an unusable file into `backups/` in the profile directory. A file from a newer version gets the suffix `.bak`. A damaged file gets `.corrupted.bak`. When the name is taken, Kobalt adds a number, for example `reader-settings.json.corrupted.2.bak`, so a backup never replaces another backup. The move is a rename, so the backup keeps the original bytes. SQLite's `-wal`, `-journal` and `-shm` files move with the database when they exist at that time. Opening a readable database first folds a log left by a crash into it. A file that is not a database loses its log when SQLite opens it. `backups/` holds only these recovery backups. `migration-backup/` keeps the import snapshots.

After the move, settings start from the defaults, the sync account is signed out and the database starts empty. The next reader shows a notice after its first page has painted. The notice names what was reset and where the backups are.

When a saved file cannot be read at all, or Kobalt cannot move it into `backups/`, Kobalt does not use the profile. Kobo shows an alert that recommends a file system repair or a device reset, and offers Kobo's built-in reader. Android and desktop refuse to open the book with the same advice. The next opening checks again.

Settings that become damaged, too large or of a newer version while a book is open stay in place. The close and the synchronous checkpoint then skip the layout memory and still save the reading position. A read error still fails those saves, so the close offers Retry.
