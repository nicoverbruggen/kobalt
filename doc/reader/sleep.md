# Sleep, USB and power

Kobalt checks for Nickel's sleep view after the sleep transition and when a native power view opens. This provides a fallback when another add-on replaces Kobalt's sleep-view hook. The fallback waits for Nickel to report a visible sleep view and does not cover a PIN prompt. `sleep-view-handoff` records the hook or fallback path, while `sleep-view-unavailable` records a check that could not hand off. These events and `sleep-start` describe the application transition. They do not prove that the hardware entered suspend.

For Nickel Screensaver 1.3.1, Kobalt checks the power-off callback chain before opening its reader. If Screensaver has replaced Kobalt's hook, Kobalt reconnects its save gate through Screensaver's call-through pointer. Both load orders retain Screensaver's image preparation and wait for Kobalt's required saves before Nickel powers off. This also applies to battery-low software shutdown. An unrecognized callback chain leaves Kobalt unavailable for that startup attempt and records `screensaver-power-hook` with `ready=false`. Kobalt does not rename libraries or reinstall another mod.

Use Kobo's built-in sleep-screen option when Nickel Screensaver should supply the image. The Kobalt options display their own image above Nickel's sleep view. Nickel Screensaver 1.3.1 recognizes only Nickel's built-in reader for its reading-page overlay. Kobalt can use the same PNG files directly in its own overlay mode. Nickel Screensaver still handles its own wallpaper settings when Nickel controls the sleep screen.

Before sleep, Kobalt saves its position and pauses its work. The page stays on screen until Nickel's sleep screen is ready. Kobalt then shows the sleep screen with one full refresh, which also clears the page, so the screen flashes once, as in Nickel's own reader. While Kobo's awake PIN screen is visible, Kobalt lets Kobo receive orientation sensor readings so the PIN screen can rotate. Kobalt keeps the saved reading orientation and stays hidden. Returning to sleep blocks those readings again. After wake, Kobalt waits for Nickel's sleep or PIN view to close and for USB storage to finish remounting. It then checks authorization and restores page-turn input before it shows the book again. The frontlight can finish fading in while the page is already visible. If wake or USB cancellation arrives while the previous operation is still releasing resources, Kobalt completes that release before checking authorization again.

On Kobo and Tolino, Settings > System > Sleep screen while reading applies while Kobalt is in the foreground. Kobo handles the lock screen elsewhere, including Home and My Books. Kobalt keeps the reader backdrop in memory for the current sleep. Closing a book or connecting USB does not save a backdrop for later use.

Kobalt with book cover is the default. It uses Kobo's full-screen cached cover if available, then the cover embedded in the book. The image fits without cropping and empty space is black. If no cover is usable, Kobalt uses the reading page. Kobalt with reading page dims the current page. An unavailable or changing page uses Kobo's sleep screen. Menus and dialogs are omitted and clock slots show a lock icon. You can also choose Kobo's built-in sleep screen to use Nickel's normal image.

The bookmark overlay uses a light background with dark text and outline in light mode. Dark mode keeps a dark background with white text and outline. Power-off keeps the dark appearance.

Kobalt with PNG over text dims the reading page and draws a transparent PNG over it. Put your PNGs directly in `.adds/kobalt/screensaver` or `.adds/screensaver` on the Kobo drive. Kobalt chooses from both folders and can use either one on its own. It does not require Nickel Screensaver or use its wallpaper subfolders. If neither folder has a usable PNG, the option is unavailable. An existing PNG selection falls back to the dimmed reading page until an image is available.

Settings > System has a Power management section with Smart Wi-Fi power saving on hosts that can turn Wi-Fi off for it. Kobo leaves the section out until beta 7 (`wifiPowerSaverReleased` in `platforms/kobo/common/reader_host_services.cpp`). It is off by default. Until beta 7 the choice is not saved and a saved one is removed, so the saver stays off. It turns Wi-Fi off when a book opens and when the device sleeps; see [Power mechanisms](../power-mechanisms.md) for the rules at sleep. When a book opens and Wi-Fi is on, Kobalt turns Wi-Fi off through Nickel before the book takes input. The book must be one that Kobalt would sync with KOSync, and automatic KOSync must be off or not set up. Wi-Fi stays on for store books and books from services that sync through Nickel's own sync, because Nickel uploads their position. It also stays on with automatic KOSync, while Bluetooth is on or its state is unknown, and while Nickel syncs. Nickel turns Wi-Fi off by itself after about two minutes without network traffic. Firmware 4.x also waits until 15 minutes after its last Bluetooth activity signal. Nickel sends one when it starts and when its own reader opens a book, whether Bluetooth is on or not, so Wi-Fi can stay on for about 15 minutes. Opening a book in Kobalt does not send one. Desktop previews do not show the setting.

Sleep indicator applies to the cover, dimmed page and PNG overlay. Bookmark is the default. Its ribbon hangs from the top edge and shows the status, percentage read and estimated time left when available. Card shows the same information in the lower-left corner. A finished book shows 100%. Both styles show battery level only while charging or charged, and update when Nickel reports a change. None shows only the cover or the dimmed page and any selected PNG. With a PNG, Bookmark and Card appear above the artwork. During foreground shutdown the cover or dimmed page says Powered off. Restart uses Kobo's restart screen.

Nickel's standard confirmations, progress dialogs and native dialog containers appear above the open Kobalt page, including Wi-Fi permission, connection and USB prompts. They keep Nickel’s widget parent and styling, with a temporary window above Kobalt. One copy of the covered reader area supplies the background until the dialog closes. Their native buttons and callbacks remain in charge. Reader shortcuts are paused until the dialogs close. Closing a dialog, sleeping or closing the reader restores the native window flags. The browser keeps its separate handoff. Cancel on the USB confirmation keeps the book open.

A confirmed USB connection waits for local reading data and native reading time to save before Nickel starts its USB workflow. This applies to a connection confirmed in Nickel's Connect dialog and to one Nickel starts without asking. The dialog reaches its Connect and Cancel actions through their function addresses, which a NickelHook call hook does not change, so Kobalt also points those address references at its USB hooks when it starts and logs the result as `usb-dialog-hooks`. Native progress keeps newer Nickel progress and allows two seconds for position conversion. Required storage saves retry on failure; the conversion deadline does not release unsaved data. Kobalt then closes the book and releases every file on user storage before Nickel exports the storage. If access to the book is revoked during the save, Kobalt still completes this cleanup and USB handoff. Reopen the book from the library afterwards.

Power-off, low-battery power-off and reboot wait for required local reading data and native reading time to save. Failed saves retry. There is no forced shutdown deadline that bypasses those saves or the engine drain. Native-position conversion still has a two-second deadline; a late conversion reply cannot write progress, but the local reading checkpoint is retained. The shared profile closes before Nickel continues shutdown. A failed or stuck save can delay shutdown indefinitely. This does not protect against physical power loss before a save completes. When the application exits, Kobalt stops its engine worker before releasing any remaining cached engine documents.
