# Sleep, USB and power

Kobalt checks for Nickel's sleep view after the sleep transition and when a native power view opens. This provides a fallback when another add-on replaces Kobalt's sleep-view hook. The fallback waits for Nickel to report a visible sleep view and does not cover a PIN prompt. `sleep-view-handoff` records the hook or fallback path, while `sleep-view-unavailable` records a check that could not hand off. These events and `sleep-start` describe the application transition. They do not prove that the hardware entered suspend.

For Nickel Screensaver 1.3.1, Kobalt checks the power-off callback chain before opening its reader. If Screensaver has replaced Kobalt's hook, Kobalt reconnects its save gate through Screensaver's call-through pointer. Both load orders retain Screensaver's image preparation and wait for Kobalt's required saves before Nickel powers off. This also applies to battery-low software shutdown. An unrecognized callback chain leaves Kobalt unavailable for that startup attempt and records `screensaver-power-hook` with `ready=false`. Kobalt does not rename libraries or reinstall another mod.

Use Kobo's built-in sleep-screen option when Nickel Screensaver should supply the image. Kobalt's Cover and Reading page options cover the native power view with Kobalt's own image. Nickel Screensaver 1.3.1 recognizes only the built-in `ReadingView` for transparent reading-page overlays; that feature is not supported while reading in Kobalt. Its wallpaper settings are separate. Physical-device coexistence and display behavior still need validation.

Before sleep, Kobalt saves its position and pauses its work. The page stays on screen until Nickel's sleep screen is ready. Kobalt then shows the sleep screen with one full refresh, which also clears the page, so the screen flashes once, as in Nickel's own reader. While Kobo's awake PIN screen is visible, Kobalt lets Kobo receive orientation sensor readings so the PIN screen can rotate. Kobalt keeps the saved reading orientation and stays hidden. Returning to sleep blocks those readings again. After wake, Kobalt waits for Nickel's sleep or PIN view to close and for USB storage to finish remounting. It then checks authorization and restores page-turn input before it shows the book again. The frontlight can finish fading in while the page is already visible. If wake or USB cancellation arrives while the previous operation is still releasing resources, Kobalt completes that release before checking authorization again.

On Kobo, Settings > System has a Sleep screen row. It opens a choice of Kobo's built-in sleep screen, Kobalt with book cover or Kobalt with reading page. Kobo's built-in screen is the default. The cover option first tries Kobo's full-screen cached cover, then the cover embedded in the book. It fits the image without cropping or dimming it. Empty space around the cover is always black in both light and dark mode. If neither cover is usable, it falls back to the reading page. The sleep-screen choice is hidden on hosts without Kobo sleep-screen support. The reading-page option shows the current page slightly darkened. Both Kobalt options show a card on the left with the percentage read. Its heading says Sleeping, Charging or Charged, using Nickel's charge state. A battery icon and percentage sit in the top-right corner of the card only while charging or charged. The icon shows the battery level and adds a bolt while charging. While asleep, the card updates when Nickel reports a battery level or charging change. Unplugging hides the battery and restores Sleeping. These updates do not poll the battery or decode the cover again. The heading uses Kobalt's serif interface font. Reading progress and time use sans-serif text. The battery percentage uses smaller monospaced text, with space before the icon. Clock slots show a lock icon in the reading-page sleep image. The reading page keeps its clock. The card also shows the estimated time left when Nickel has a reading pace. With the default Detailed time format, estimates up to 120 minutes use minutes; longer estimates use hours and minutes. Approximate uses the shared Time remaining format setting. Menus and dialogs are omitted. An unavailable or changing reading page uses the stock sleep screen. Kobo still controls sleep, wake and PIN entry. Closing a book saves the selected Kobalt backdrop before returning to Kobo. USB handoff also saves it before storage is exported, after the required saves complete. The same backdrop is used when locking or turning off from Home or the library while that book remains the last book opened. Turning off with a Kobalt book open uses its current backdrop. The card says Powered off during shutdown. Its background is black and its text is white in both light and dark mode. Restarting keeps Kobo's normal restart screen. Opening any book again invalidates the saved image, including opening the same book in Kobo's reader. A missing, damaged or outdated image uses Kobo's built-in screen. The saved image survives a Nickel restart if Kobo's last-read record still matches. The charging card uses the current battery state and continues to update while asleep. The setting does not change Kobo's sleep-screen configuration. Profiles that had Kobalt's sleep screen enabled start with the cover option.

On Kobo, Settings > System has a Power management section with Smart Wi-Fi power saving. It is on by default. It turns Wi-Fi off when a book opens and when the device sleeps; see [Power mechanisms](../power-mechanisms.md) for the rules at sleep. When a book opens and Wi-Fi is on, Kobalt turns Wi-Fi off through Nickel before the book takes input. The book must be one that Kobalt would sync with KOSync, and automatic KOSync must be off or not set up. Wi-Fi stays on for store books and books from services that sync through Nickel's own sync, because Nickel uploads their position. It also stays on with automatic KOSync, while Bluetooth is on or its state is unknown, and while Nickel syncs. Nickel turns Wi-Fi off by itself after about two minutes without network traffic. Firmware 4.x also waits until 15 minutes after its last Bluetooth activity signal. Nickel sends one when it starts and when its own reader opens a book, whether Bluetooth is on or not, so Wi-Fi can stay on for about 15 minutes. Opening a book in Kobalt does not send one. Desktop e-reader previews show the setting; phones and desktop windows do not.

Below it, Sleep screen style chooses how the Kobalt options show their status: Card, Footer band or Bookmark. Card is the default and is the card described above. Footer band is a strip across the bottom edge. Its top line is thicker for the part of the book already read. The status uses the serif interface font on the left. Progress and time left use small monospaced capitals on the right. Bookmark is a ribbon that hangs from the top edge near the right side, with a notch cut into its end. It is black in light mode and dark gray in dark mode, with a white outline. It shows the status as a small caption, the percentage read in large serif figures and the time left below. In both styles, the battery shows only while charging or charged. In the band, it stands upright after the status, as tall as its letters, with its percentage on the right. The space before it equals the space between the screen edge and the status. In the ribbon, it sits at the end. Each style keeps one fixed area, so a battery update repaints and refreshes only that area. Powered off makes the band black with white text and keeps the black ribbon. Sleep and power-off from Home use the style selected when the device sleeps. Images saved by earlier versions have no percentage; the band then shows no progress line and the ribbon shows the progress text instead. The style has no effect with Kobo's built-in sleep screen. Like the Sleep screen row, it is unavailable on hosts without Kobo sleep-screen support.

Nickel's standard confirmations, progress dialogs and native dialog containers appear above the open Kobalt page, including Wi-Fi permission, connection and USB prompts. They keep Nickel’s widget parent and styling, with a temporary window above Kobalt. One copy of the covered reader area supplies the background until the dialog closes. Their native buttons and callbacks remain in charge. Reader shortcuts are paused until the dialogs close. Closing a dialog, sleeping or closing the reader restores the native window flags. The browser keeps its separate handoff. Cancel on the USB confirmation keeps the book open.

A confirmed USB connection waits for local reading data and native reading time to save before Nickel starts its USB workflow. This applies to a connection confirmed in Nickel's Connect dialog and to one Nickel starts without asking. The dialog reaches its Connect and Cancel actions through their function addresses, which a NickelHook call hook does not change, so Kobalt also points those address references at its USB hooks when it starts and logs the result as `usb-dialog-hooks`. Native progress keeps newer Nickel progress and allows two seconds for position conversion. Required storage saves retry on failure; the conversion deadline does not release unsaved data. Kobalt then closes the book and releases every file on user storage before Nickel exports the storage. If access to the book is revoked during the save, Kobalt still completes this cleanup and USB handoff. Reopen the book from the library afterwards.

Power-off, low-battery power-off and reboot wait for required local reading data and native reading time to save. Failed saves retry. There is no forced shutdown deadline that bypasses those saves or the engine drain. Native-position conversion still has a two-second deadline; a late conversion reply cannot write progress, but the local reading checkpoint is retained. The shared profile closes before Nickel continues shutdown. A failed or stuck save can delay shutdown indefinitely. This does not protect against physical power loss before a save completes. When the application exits, Kobalt stops its engine worker before releasing any remaining cached engine documents.
