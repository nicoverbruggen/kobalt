# Settings and controls checks

`desktop.settingsStandby` checks supported and unsupported hosts, the default state, confirmation, cancellation, unanswered-warning dismissal, persistence after reopening and re-enabling standby. The gallery includes the System settings pages and the standby confirmation.

`desktop.settingsAutomaticOpening` gives the reader a host reader choice. It checks that turning Open books automatically in Kobalt off shows a confirmation, that Cancel and closing Settings keep it on and save nothing, that confirming turns it off and that turning it on applies at once. The gallery includes the confirmation.

`desktop.settingsZenPage` opens Settings in Zen mode with a frontlight and the edge swipes off. It checks that the page has no rail, shows the ZEN caption, Dark mode, Light, About and the hold button, and shows Sync now and Automatic sync only while an account is signed in. Dark mode must apply at once and follow the Display checkbox. About must open with a back cell and without the hold button, and back must return to the page. Light must close Settings and open the Light panel. A press released before the last step must keep Zen mode. A press held through all steps must turn Zen mode off in the draft and show the rail on Display; closing Settings must save it. Settings opened outside Zen mode must show the rail and no Zen page. The tests shorten the half-second step with the button's `reader_hold_step_ms` property instead of waiting.

`desktop.settingsZenMode` turns Zen mode on from the first Display row. It checks the centered groups, the hidden toolbar actions and tabs, and the Chapters and Bookmarks tabs. It checks that the header and footer are blank while the menu is open and return when it closes. It checks that turning Zen mode on and off, a chapter jump and a search jump from the Zen menu each request a full cleanup, and that the cleanup waits while Search covers the page. Leaving Search with Back requests the cleanup as Search closes. Closing Bookmarks with its Zen tab must be a tab-panel dismissal, as closing Chapters is. Opening Chapters and returning from Settings to the Zen menu must each request one screen update. Under Chapters the tabs must keep their place, attach to the view and lose their rounded corners. Paper with the heavy rule along its top must cover the page beside them, from the end of the view to the bottom edge. Chapters and Bookmarks must both end on that rule. It turns the reading stats on and checks the counted page turns, including a page button turn while the menu is open. The panel must stay on after the menu closes and reopens, and the test checks that the choice is saved and cleared. It presses Annotate to turn highlight mode on and off. It then turns Zen mode off with a held press in Settings and checks that the regular toolbar, tabs, Settings width and header and footer return. A second row hides Annotations and Bookmarks and checks that only Chapters and Search remain. A third row hides only Bookmarks and checks that the tab reads Annotations. The gallery captures the Zen menu, its reading stats, the low-battery status line and Chapters opened from it. The low-battery capture checks that the ZEN mark and the battery icon are the same distance from the group's edges.

`desktop.settingsFeatures` checks the checklist, persistence, re-enabling and dependent defaults. The gallery captures the checklist beside System settings. `desktop.settingsFeatureLists` hides Bookmarks or Annotations on their own and checks the shared list, the toolbar button's label and that the button keeps the toolbar style of the Settings button. `lifecycle.kosyncAccountGating` includes a signed-in account with KOSync disabled and checks that opening, reading and closing make no connection.

`model.text-presets` checks text presets: the examples, cleanup of damaged lists, matching a book's text in any screen density, unique ids and names and the new-book choice. `desktop.reading` drives the Text panel: it opens the preset cards, applies Large and Comfort, marks a change, refuses a taken name, saves a new preset, opens All and renames a preset from the edit cell of a tile's actions. `desktop.settings` chooses Book default in the Text for new books grid. The gallery captures the cards, a changed preset, the save dialog, All presets, a preset's actions, Settings > Defaults and Text for new books.

Label `settings`. Build `mac-tests`, then run `ctest --preset mac -L settings` from `platforms/desktop/`. `ctest --preset mac -N -L settings` lists its tests.

These checks cover Settings drafts, apply and persistence, appearance previews and their failures, the Light shortcut for dark mode, shared controls, borders, themes and the acknowledgment and license pages. `component.ui` renders the shared controls in pixels in both themes and at 212 and 300 PPI. Its border checks use fractional scales and pixel offsets, because rounding a strip width separately from its boundaries gives uneven borders. It also checks that an option row measured before it is polished uses its style sheet font. On Kobo the application font is Nickel's, so a row measured with it was too short and clipped the dialog around it. The `lifecycle.appearance*` checks drive previews and their failures in the production reader.

Appearance changes use separate contracts. `appearance::Patch` changes only named appearance fields. `appearance::Requested` holds the complete request and cannot carry a reading position. `appearance::Displayed` pairs resolved settings with the completed frame revision. `appearance::SavedInput` preserves absent and null fields when restoring persisted input. The existing `AppearanceEditSession` continues to own preview and apply lifetimes. Model checks cover partial edits and persisted fields; session checks queue edits before a frame completes and verify that displayed and checkpoint settings stay with the old frame until completion. Temporary typography checks verify that checkpoints preserve the original saved appearance.

Dark-mode saves from Settings and from the Light shortcut run on the profile writer thread. These headless checks do not establish physical touch delivery, e-ink refresh quality or device storage latency.

Centered choice and confirmation dialogs use the shared `PopupCard` heading for title and description spacing. Its plain text wraps into balanced lines using the same font measurements as painting. Explicit paragraph breaks stay intact. Long prose keeps ordinary wrapping. The component checks cover orphan-line avoidance, line width, paragraph preservation and text without word spaces. Described option rows reserve extra vertical space when their supporting text determines the row height; rows without descriptions retain their size.

Dismissal checks verify that appearance and Styling previews release their source images. Dictionary and footnote panels release their text and layout on dismissal, retain content while their parent is temporarily hidden, and populate again on reopening. These are ownership and behavior checks, not measurements of process RSS or Kobo memory.

Reader teardown checks observe child-panel callbacks through window destruction, with Text and Layout previews ready or still rendering and with Settings open. They reject callbacks after reader teardown starts without relying on an allocator to detect a destroyed member. These checks cover the observed panel subscriptions, not every possible widget callback lifetime.
