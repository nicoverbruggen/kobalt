# Reading position, progress and history

Kobalt saves the position in its own per-book file while reading. It writes the position back to Nickel when the book opens, before sleep, before USB, at power-off and when the book closes. Background saves skip an unchanged position and never run during a page turn. The local position is written on a separate thread after two seconds without input, or after a short pause when 30 seconds have passed without a save. Kernel standby between page turns does not advance this wait. A failed background save is logged as `local-save-failed` and shows no message; the next save, sleep or close writes the same position again. Sleep shows a message when its save fails, and closing offers Retry save and close. When Nickel wants to enter standby while a save is waiting, Kobalt keeps the device awake until it has started the save, instead of writing it after the tap that wakes the device. The writeback to Nickel must use Nickel's database from the interface thread, so it does not run on page turns. If the opening write is blocked or fails, Kobalt retries every two seconds after input settles until a native save succeeds. Retries wait while the reader is hidden, suspended, busy or blocked by a progress choice or appearance panel. Nickel's copy of the position stays at the last opening, sleep or close until the next one. If Kobalt stops without a sleep or close, the local position is still current, and the next opening uses it, because Nickel's position is not newer than the one Kobalt last wrote. A busy database or an unresolved change to Nickel progress keeps the local position without overwriting Nickel. The first opening imports Nickel's saved position. On later openings, a newer Nickel position wins over the local one. Like Nickel's reader, the write at opening marks the book as the one being read, so Home and the sleep screen show it. Sleep saves the local position and attempts native progress writeback before Nickel prepares its sleep screen. Like Nickel's reader, Kobalt opens every saved position: when the exact place is missing, it opens the start of the chapter, and when the chapter is missing, the start of the book. It shows no message, and logs a `native-position-fallback` event with the chapter file. A downloaded book that has no position yet opens at the start. Nickel stores `#` for such a book, for example when a store server sends a reading state without a location.

Kobalt recognizes a changed book by the file size and the ZIP directory, which holds the checksum of every file in the book. When the book changes, for example after an update from the store, Kobalt discards its saved position and typography for that book and imports Nickel's position.

The per-book file also records the CREngine DOM version that wrote the position. Kobalt opens the book with that version again, so a saved position stays valid after an update to CREngine. A new book uses the current version. Saving progress preserves extra fields in the book's supported saved record. Mark as unread still resets the record without removing bookmarks, annotations or reading history.

On Tolino firmware 5 and 6, Kobalt saves the native `content` record and `tolino_bookmark` together. The native bookmark writer keeps the reading status, position, page counts, fractional progress and sync metadata consistent. Page counts describe Kobalt's current layout; the built-in reader recalculates them when it opens the book. Both records must verify before Kobalt reports a successful native save. Tolino's Kobo reading-session statistics remain disabled.

On firmware 5 and 6, Nickel stores a chapter path, an element ID and a text offset, so a supported position round trip is exact. On firmware 4, Nickel stores only a chapter path and an element ID. Kobalt gives Nickel the element that contains the position and keeps the exact offset locally. In a KEPUB, if a page starts outside a `kobo` span or CREngine normalizes the span text, Kobalt saves the start of the current chapter to Nickel and keeps the exact position locally. A plain EPUB gets Nickel's element path form instead, as described below, and the chapter start only when that element's text differs. This lets Nickel update the current book, sleep cover and percentage without saving an invalid text offset. Ambiguous chapter paths, duplicate IDs and resource read failures still prevent native position writeback.

Kobalt writes Nickel's progress under Nickel's own database lock, through Nickel's own functions, and reads the result back on a separate connection. [Sync data](../sync-data.md) lists every field Kobalt writes, the Nickel functions it uses, and what Nickel then uploads. Along with the position and percentage, it writes the progress through the current chapter as Nickel's reader does: the pages of the chapter before the current page, divided by the chapter's pages. Nickel's sync uploads that value as the chapter percentage, and Nickel's reading statistics show it. If the write fails, the local position stays. The write marks the book for normal sync. Kobalt does not claim that the server received it. In a plain EPUB whose text has no element IDs, Kobalt writes and reads Nickel's own DOM point form, such as `OEBPS/chapter1.xhtml#point(/1/4/24/1:0)`. It also uses this form for a paragraph without an ID inside an element with an ID, such as a chapter `<section>`, because Kobalt does not keep the whitespace between that element's paragraphs. It counts every child from `<html>`, text included, and the offset in UTF-8 bytes, on firmware 4, firmware 6 and Tolino. When the source text differs from what Kobalt displays, Kobalt writes the chapter start instead. When a position cannot be mapped to Nickel's format at all, Kobalt records only the time, the reading status and the percentage for a sideloaded plain EPUB. Nickel keeps its own position, and the book is not marked for sync. Other books keep the position locally.

While reading, Kobalt checks Nickel's progress when Nickel reports a sync, an account update or a USB connection, including one that happened while the device slept. If Nickel's signals are unavailable, it also checks once a minute. If the committed position changes, it asks "Keep reading here" or "Go to synced position", including when the timestamp is unchanged or older. It never jumps without asking. If a KEPUB sync round trip only removes the character offset from the same span at the same timestamp, Kobalt keeps its precise local position without asking.

Books downloaded through servers compatible with Kobo's built-in sync mechanism use the server's book ID unchanged. Kobalt accepts safe string IDs in Nickel's download directory, including numeric IDs. It does not require UUID syntax. The EPUB format and protection checks still apply.

On exit, Kobalt asks whether to mark the book finished when the zero-based page index is at least 90% of the total page count. A forward turn with no next linear page also asks, including before trailing non-linear sections and in very short books. Select Don’t ask again for this book before choosing Still reading or Mark as finished to stop future finish prompts for this book. The choice survives closing and restarting. Other books keep their prompts. Mark as unread clears this choice with the book’s other settings. Opening a finished book starts it at the beginning and marks it as reading again. This also applies to books marked finished in the host library. Book appearance, dictionary choice, finish-prompt suppression, bookmarks and annotations are preserved. Books still in progress keep their saved position.

Kobalt also reports reading sessions and page turns to Nickel, including the estimated words on the page just left. Page-turn reports fire Nickel's event from the interface thread, as Nickel's reader does. Nickel's event thread saves Nickel's events when a reading interval starts and adds the interval's reading time when it ends, so the first turn after wake does not wait for Nickel's database. Kobalt does not check the signed-in account for these reports: signing out of Kobo deletes Nickel's database and restarts the device, and Kobalt closes the book when authorization changes, so a reading interval never outlives its account. Nickel keeps its reading history and calculates the reading pace. Each active reading interval also sends Nickel's reader-shown and reader-hidden events, so Nickel records its start and end timestamps when reading history is enabled. Sleep ends the interval; wake starts a new one when reading resumes. Session events use the displayed page's native percentage and mapped bookmark, even when the final book-position save has not run yet. Preparing an event changes only its temporary volume; it does not save the book position or add page-turn writes. Kobalt refreshes that pace in the background while reading and waits at least a minute after each query completes before requesting another. Page turns use the last valid pace without waiting for Nickel. Kobalt applies that pace to its current chapter word counts and position, and saves the chapter and book time estimates with native reading time. Jumps and layout changes report no words for pace training. On firmware 4, Kobalt accepts either the current reading-session functions or the older pair without a reader-state argument. It requires a complete pair with the same calling convention.


- Stats uses the same word counter on Kobo, Android and the desktop testing app. It shows the current chapter, a chart of chapter lengths, the pages left in the chapter and book, the book's word count and the minutes read since opening. Letter and number runs form words across inline markup. One internal apostrophe or hyphen joins a run. Combining marks and format characters do not split it. Han and kana letters count individually; Thai and other scripts have no dictionary segmentation. The total includes visible text before chapter headings and in non-linear spine sections. It excludes hidden elements, SVG text and ruby annotations. Chapter intervals follow the EPUB's table of contents. Duplicate destinations keep separate entries, with the interval assigned to the last duplicate. A word crossing a chapter anchor belongs to the interval where it began. Kobalt counts once before showing the first reader page and saves completed counts with the parsed document. Page turns, reflow and a compatible cached opening reuse them. If counting fails, the word total stays hidden and the chart uses chapter lengths in pages. The chart uses one scale for the book, capped at three times the median chapter. A longer chapter fills the full chart height, and its reading progress fills it in proportion. It shows every chapter on one row and pages only when bars would be narrower than 6 pixels. With Compact chapter graphs turned off, it shows 20 chapters per page. On a short screen, the bars can lose up to two thirds of their height so the chapter and book cells fit above the tabs. The unit beside a figure takes a second line before it shortens. On Kobo, the chapter and book cells use Nickel's reading pace, including its existing history and default pace when there are too few samples. The estimates use Kobalt's word counts and chapter progress, so they can differ from Nickel's reader. On Android and desktop, time estimates start at a rough 250 words per minute and adapt to accepted reading samples. In the header and footer, a `≈` prefix marks estimates until at least 5 minutes and 3 page samples have accumulated. Stats marks all time estimates with `≈`. The profile saves this history across books and app sessions, including partial history. Samples use the chapter's words per page and time between consecutive forward turns. Rapid paging, jumps, backward turns, pauses, layout changes and idle periods longer than 5 minutes do not add samples. The history retains up to 30 minutes of accepted reading time, then gradually reduces the weight of older samples. Missing word counts leave the estimate unavailable.

## Reading history

Android, desktop and Kobo save reading intervals in Kobalt’s profile database. Kobo also keeps reporting sessions to Nickel. Opening a usable reading page starts an interval. Backgrounding the app, hiding the reader or closing a book ends it. Returning starts another interval. Foreground menus remain part of reading time. Reading without a page turn still counts. Active intervals save in the background at start and once per minute. Routine page-turn checkpoints do not write history. Closing waits for the final interval to be saved. After an interrupted run, history keeps only the last saved duration and excludes time while the app was closed. See [Storage compatibility](../storage.md#reading-sessions) for the fields and migration rules.

If another Kobalt app already owns the profile, opening a book asks you to close that app first. Separate Mac worktree builds use separate profiles and can run alongside each other.

History stays saved when a book is marked unread or removed from the library. Changed editions stay distinguishable. Recording starts with this feature; previous reading-speed samples cannot supply historical sessions. The Stats interface is unchanged and does not show this history yet. Kobo continues to use Nickel's reading pace for time estimates.
