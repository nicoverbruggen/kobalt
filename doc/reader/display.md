# Display refresh

Closing a footnote panel requests a full screen refresh to clear the popup and the selected link, as closing the dictionary does.

Automatic clock and reading-estimate updates repaint only the changed header and footer pixels. They do not use the page-turn refresh policy for images or colour. The clock updates each minute in every slot, including a custom layout.

On BOOX, Android uses a separate refresh policy. Ordinary light-background text turns request REGAL for the reading body. Changed header and footer content uses GU in separate rectangles, leaving unchanged content outside those rectangles. Controls use GU throughout the app, including the Library and book-opening screen. Returning from a book keeps the previous frame visible until Android restores its system bars and the Library has its final layout, then requests cleanup. A requested cleanup covers the whole Android surface with GC. Tapping the centre of the page to dismiss the reading menu requests this cleanup, as on Kobo. BOOX app optimization must allow the app to control refreshes. These Android rules do not change Kobo page turns.

Kobalt paints one completed frame per page turn. Ordinary turns use Kobo's reading policy for the detected display backend. On firmware 4's i.MX backend, Kobalt queries Nickel's hardware capabilities and the native DisableRegal setting. It uses partial REAGL when Regal is supported and enabled, or partial GLKW16 in dark mode when Eclipse is supported. Other i.MX revisions use driver-selected automatic updates. Ordinary MediaTek page turns use partial GLR16/GLRC16 or dark GLKW16 in one submission. Unknown backends keep Kobo's automatic policy. Ordinary turns on i.MX and unknown backends use one whole-screen update with their existing mode and waveform. On MediaTek, a page turn with a large image or with colour refreshes the whole screen once in full update mode, as Nickel turns. It uses the same reading waveform as an ordinary turn, so it does not flash. Full update mode updates the whole screen, not only the pixels that changed. A turn uses this full refresh when the outgoing or incoming page has an image covering at least 10% of the reading image. On colour devices, any colour region also uses it, including coloured text and backgrounds, and so does a page with coloured highlights. Page turns do not request a cleanup for pictures, coloured book content or highlights. Adding, changing or removing a coloured highlight still cleans up its area. Requested cleanups use GC16, GCK16 in dark mode and GCC16 for colour. Entering dark mode requests one whole-screen cleanup. In light mode, opening the plain reading bars over a text-only page uses one screen-spanning partial text update without cleanup, so the top and bottom appear together. Bottom panels keep localized updates. Opening the menu in dark mode requests one whole-screen cleanup. Closing the menu with a tap on the page or the title requests one full cleanup to clear ghosting. In dark mode, returning from the menu also requests cleanup when it closes another way. In light mode, closing a reading-menu panel another way, or jumping from Chapters or Search, does not flash. Refresh the screen, on the Display tab, decides which page turns also flash. Smart, the default, flashes on a forward turn onto the first page of a chapter, but only after at least 10 turns since the last flash, so a run of short chapters does not flash on every turn. Every page flashes on each completed forward or backward page turn. Rejected page-turn gestures, including turns past the book edges, do not add a flash. Every chapter flashes at every chapter start. Every 6, 10 or 20 pages flashes on that many turns since the last flash, in either direction. Manually does not add page-turn flashes. Dismissing a visible sync notice requests one full cleanup, including after success, cancellation or a timeout. Sleep and closing keep their own screen handoff. Any flash restarts the count. Each flash logs a `full-flash` event with its reason, and replaces that turn's page animation.

An already visible layout progress bar repaints only the strip where its fill changes, in either direction. Its border and unchanged fill stay untouched. Values received in the same event-loop pass paint together, and values that leave the fill on the same pixel do not repaint. On MediaTek, percentage-only updates inside an already visible layout progress bar use partial mode in light mode over a text-only page. Showing or hiding the modal, changing its message or layout, dark mode and the full refresh for pictures and colour keep their existing refresh policy. Stats keeps unchanged graph data and progress without repainting. Text, Layout and Stats use their final position before they become visible. Opening Text or Layout keeps the current book frame until an appearance setting or viewport size changes. Appearance panels keep their position when an unchanged reading state is reported. Chapters and the font picker keep their stacking order. Replaying those states does not repaint the panels. Adjacent or split widget rectangles with the same supported refresh policy merge into one submission after Qt finishes painting them. Damage with different update modes or waveforms keeps each rectangle's policy. Header and footer changes keep separate damage regions when no page turn is in progress. Showing or hiding link highlights repaints the whole page in one refresh, because MediaTek refreshes each page rectangle separately. A change between two sets of highlights updates only their old and new outlines. Annotation changes repaint one compact rectangle that covers the old and new marks. Unchanged annotation state does not repaint. Closing highlight mode without an unfinished selection leaves the reading page unchanged. Discarding an edit restores the original saved highlight. A destination page arrives with its visible saved highlights and draft selection. They paint together in the first reading frame, including page animations. Opening a book with saved highlights prepares that markup before replacing the opening view. Pages without visible markup keep the ordinary page path. Paging Stats, Chapters, Bookmarks or licenses leaves unchanged headings and figures alone. Opening progress batches values within the current event-loop pass, without a timer. Opening a bottom panel or returning from the font picker keeps the toolbar rules in place. Compatible key damage within the visible search keyboard uses one rectangle instead of one refresh per key. Showing an already visible keyboard keeps its stacking order. Unchanged keyboard-only paints skip submission when their pixels already received the same refresh policy. Changed keys and cleanup still refresh. Brightness and warmth notices skip unchanged rounded levels.

On ordinary Android screens, Settings > Display > Page turn animations is a checkbox, off by default. It enables a 180 ms software sweep with an ease-in/ease-out curve. Sweep replaces stationary columns in the same band order as the e-paper sweep. Update timing follows the active display's reported refresh rate. The effect runs after a tap or completed swipe. It animates the reading body and its highlights; headers and footers stay still. A new touch, hiding the reader or a geometry change ends the effect on the completed destination page. The selection is global and uses the optional `page_turn_animation` preference, with `off` and `sweep` values. Missing or unknown values use Off. Earlier `curl` and `fade` selections load as enabled Sweep. This does not change Kobo's `page_animations` preference. ONYX/BOOX devices keep their native e-ink refresh path. A BOOX-specific native animation is not implemented.

Page animations use NickelDissolve's runtime compatibility policy. Devices with MediaTek's `hwtcon` display driver show “Page animations are supported on this device.” These include Clara Colour, Libra Colour, Clara BW and their Tolino counterparts: shine color, vision color and shine. Devices with the i.MX `mxcfb` interface can also enable animations, with a warning: “Page animations may not be supported on this device. Turn this off if they do not work correctly.” This includes Libra 2 and Clara 2E, but compatibility depends on the hardware revision. The driver decides availability, not a model allowlist. Unknown drivers and Allwinner/sunxi remain unavailable. Animations follow NickelDissolve's sweep and work in light and dark mode. Text and images below 10% of the reading image can use the sweep. A turn that uses the full refresh for a large image, colour or coloured highlights skips the animation. Colour alone does not trigger this policy on monochrome devices. Both the outgoing and incoming pages are checked. Kobalt keeps the final page pixels throughout the turn and does not flash image regions separately after a sweep. These are Kobalt's conservative thresholds, not a claim about Nickel's internal thresholds. A failed band or wait requests whole-page cleanup instead of leaving stale bands. Each animated turn logs a `page-animation` event. Animations are off by default. A missing display hook also disables the option. Tolino and i.MX animation behavior still need physical-device validation. `-DKOBALT_PAGE_ANIMATIONS=OFF` removes them from a build.

The compatibility reference is [NickelDissolve at `3449254`](https://github.com/nicoverbruggen/NickelDissolve/tree/3449254ef098a4360ff5264abc34cda92f994de4), built with Qt5 Widgets for firmware 4. Its source classifies hwtcon as supported and mxcfb as uncertain, more broadly than its README's named models. It has no firmware-version cutoff; it recognizes update requests and symbols. Kobalt keeps its own supported firmware/package requirements and requires its display hook. Both Qt5 refresh-policy ABIs can submit page animations. On mxcfb it recognizes only the 72-byte send request, preserves the original waveform and fields, and animates only partial GL16, REAGL, REAGLD or GLKW16 reading updates. Full flashes, automatic and unknown waveforms pass through. It uses the reference's 30 ms delay between bands because mxcfb has no submission wait. This does not establish animation quality or speed on a physical panel.

Kobalt installs its animation hook when its reader first opens, after startup mods have loaded. It preserves the existing display hook so older NickelDissolve installations keep controlling the built-in reader's animations. The two animation settings are independent. An `animation-hook` event records whether installation succeeded; if it fails, Kobalt leaves its animation setting unavailable. This supports mods loaded at startup. Mods that replace the same hook later without preserving it can still conflict.

Ordinary page turns reuse chapter pages and the available font list in memory. Chapter pages update when the pagination or the chapter list changes. A turn with unchanged appearance and viewport skips appearance validation; rotation can change the viewport without opening Settings. Adjacent page images are prepared after the current page is painted. Page images use the byte order of the screen's backing store when the platform reports one, so painting a page copies its pixels without converting them. The Kobo Qt 6 integration reports RGBA bytes at the first window flush. One retired page buffer can be reused when no session or interface holds its pixels. Resize, appearance changes and image-resource changes discard it. Images discovered on adjacent pages load before those pages are requested.

Settings > System > Reader has a Time remaining format choice below Open books automatically in Kobalt. Detailed is the default and keeps the existing formats in each view. Approximate applies to chapter and book estimates in the header and footer, and to Kobalt's sleep screens. It rounds positive estimates up to 15, 30 or 45 minutes below an hour, then to whole hours. For example, 46 minutes shows about an hour, and 61 minutes shows about 2 hours. Unknown estimates keep their existing learning or hidden state. Zero estimates show no time in Approximate mode. The choice does not change reading pace, saved estimates or elapsed reading times. It takes effect when Settings closes and applies to all books.


On MediaTek, damage inside one panel, such as a slider and its value, refreshes as one rectangle. In light mode, a change inside an open Text or Layout panel, such as a slider row or the font sample, uses a partial update so only its changed pixels refresh. Showing or hiding the whole panel keeps its full update. Damage in separate panels and on the page stays separate within the same painted frame. Opening the main reading bars uses one screen-spanning text update so the top and bottom appear together. Bottom panels preserve separate damage regions and leave unchanged reading text alone. Adjacent damage with the same policy can share one rectangle. The waveform and closing cleanup stay unchanged.
